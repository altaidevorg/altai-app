# CP-08-44 — CLI control-protocol adapter (embedded host)

**Status:** complete
**Backlog package:** 053 (Desktop/IDE/Studio/CLI adapters) — PR 1 of 3–4
**Depends on:** CP-08-36/37 (package 051 protocol + dispatcher), CP-08-38/43 (package 052 local migration lifecycle)

## Outcome

The CLI's framed stdio serve mode is now an `EmbeddedHost` deployment of the
public versioned control protocol. Two new RPC methods — `control/negotiate`
and `control/execute` — frame `CapabilityNegotiationRequest` and
`ProtocolRequest<ProtocolCommand>` through the same `ProtocolDispatcher` the
deployed backend serves, backed by the same workspace `work.db`. This is the
first host adapter toward package 053's gate: the same command causes the same
transition on every host.

## Rationale

CP-08-37 left the protocol served by exactly one transport (the deployed axum
router). Every additional host that re-implements command semantics drifts;
every host that embeds the dispatcher cannot. The CLI is the natural first
adapter because its serve mode already speaks a framed RPC with per-domain
handler modules, and because it becomes the control plane's first CLI-side
consumer — which also unblocks the CLI's deferred work.db migration gate from
CP-08-43's Out-of-scope.

## Scope

- `altai-cli` gains `altai-control-plane`/`altai-control-protocol` deps.
- `serve/protocol.rs`: `ControlProtocolState::open` migrates `work.db` via
  `LocalMigrationRunner` (a newer schema refuses startup loudly), opens the
  protocol-facing repositories, and builds a dispatcher with honest
  capabilities (`capabilities_from_wiring`: only `activity_audit` and
  `event_replay` advertised — unserved domains answer typed dispatcher
  errors). `negotiate`/`execute` own framing only; no domain logic.
- `serve/mod.rs`: state built once at serve startup; dispatch arms for
  `control/negotiate` + `control/execute` (parse failures are transport-level
  `-32602`); both methods advertised in the `initialize` capability list.
- Conformance test: identical `ProtocolRequest` through the CLI state and a
  reference dispatcher on the same database produce identical JSON responses;
  newer-schema refusal, empty-activity serving, and framed request shape are
  pinned.
- Repairs pre-existing latent test debt: `serve::work`'s pinned
  `CAPABILITIES.len() == 10` assertion had been wrong since 2ec91f40 added
  `work/children/list` (CI never runs member-crate unit tests — see below).

## Out of scope

- Desktop (Tauri) and IDE/Studio adapters — package 053's remaining PRs.
- Serving domain commands beyond negotiate/query-activity/replay-events: the
  dispatcher itself answers typed errors until a package adds serving.
