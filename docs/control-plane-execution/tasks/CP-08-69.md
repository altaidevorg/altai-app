# CP-08-69 — Worker IPC transport and health probing

- **Package:** 072 — Out-of-process plugin workers (PR 3)
- **Status:** in review
- **Depends on:** CP-08-67 (#815), CP-08-68 (#816)

## Outcome

The wire the health observation travels on. `WorkerFrame` is the
host↔worker protocol — one JSON line each way over the worker's piped
stdio (`health_probe` / `health_ok`) — and `StdioWorkerTransport` is the
host side: a reader thread owns the worker's stdout so a probe can
*time out* on every platform, which a direct read cannot do.

`SupervisedWorker::reconcile` now closes the loop the supervision core
designed for: with a `HealthProbePolicy`, a live worker past its
startup grace is asked how it feels. An answer is the `Healthy`
observation (including `Healthy`-from-`Crashed` when a replacement
answers — the restart completing, from real evidence); silence inside
the window kills the worker and is observed as the crash it is,
answered by the restart budget like any other crash. Exits are still
checked first — a process that has died is never probed.

## Rationale

- **Policy stays in the supervisor.** The transport reports
  answered/silent; what silence *means* (crash, restart, budget) is the
  supervisor's existing table, unchanged. Probing is opt-in: without a
  policy, a process that has not exited is considered running — PR 2's
  semantics preserved for callers that do not probe.
- **A worker still booting is not yet silent.** `startup_grace` holds
  probes back for a fresh process (relaunches included); `probe_window`
  bounds each wait. Both are host-side timing facts, not new
  observation vocabulary.
- **Junk on stdout is not a host error.** The reader ignores
  non-protocol lines — a worker may write anything to its stdout, and
  an unanswered probe is the designed consequence. The wire shape is
  pinned by test (`{"type":"health_probe"}` / `{"type":"health_ok"}`).
- **Broken pipe on probe = no answer, not an error.** The worker cannot
  answer through a closed pipe; its exit observation on the next
  reconcile explains why. `WorkerProcess::stop` became kill-plus-reap
  and deliberately infallible: killing an already-dead process is the
  no-op it should be (and reaping means no zombie lingers), while
  `try_wait` remains the only fallible process operation.

## Real-process testing

The re-exec trick grows a `probe` mode: the child serves health probes
over its real stdio until the pipe closes. `--nocapture` is required —
libtest would otherwise swallow the child's stdout into its capture
buffer and silence the worker. Tests: an answering worker goes
`Healthy`; a silent one is killed and its silence exhausts a zero
budget; a silent-then-answering sequence shows `Healthy`-from-`Crashed`
off a real probe; grace defers the first probe; an exiting worker is
reported through its exit, never a probe. Five consecutive full runs
green.
