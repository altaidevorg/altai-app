# CP-08-59 — Chat operations intents land on the Work OS Home

- **Package:** 067 — Chat Work/Task/Automation mini-apps (PR 1)
- **Status:** in review
- **Depends on:** 062, 063, 066

## Outcome

Chat shortcuts and panel chrome that dispatch `altai:open-operations`
intents (`view`, optional `workHubView`) now land on the Work OS Home in
the desktop agent mode instead of opening studio's legacy project board.
`/scheduled` opens the Routines surface; every other view (overview,
work, runs, inbox) opens the Work surface, whose left column already
carries the inbox and the runs hub. Studio keeps its existing routing.

## Rationale

The chat surface already speaks the operations vocabulary —
`AiSidePanel.openOperationsSurface` and the slash commands dispatch
`altai:open-operations` with `view`/`workHubView`. But `App.tsx`'s
listener unconditionally called `openProjectBoardFromContext`, which
opens studio and the legacy `ProjectBoardPanel`. An agent-mode desktop
user following a chat shortcut was yanked out of the desktop into
legacy UI, splitting one navigation vocabulary across two hosts.

Package 067's contract is that chat embeds shortcuts and projections
and owns no durable state. This PR makes the chat *point* at the
canonical surfaces: the mapping from intent to Home surface lives in a
tested pure projection (`homeSurfaceFromOperationsIntent`), and
`DesktopHome` applies it through an intent prop with a nonce, so the
chat owns no surfaces or state of its own.

## Scope

- `src/modules/work-board/lib/operationsIntentProjection.ts` (new):
  `OperationsIntentView`, `OperationsWorkHubView`, `HomeSurface` types
  and the pure `homeSurfaceFromOperationsIntent` mapping
  (`workHubView === "scheduled"` → Routines, otherwise Work).
- `src/modules/work-board/lib/operationsIntentProjection.test.ts`
  (new): the two behaviors above.
- `src/modules/work-board/index.ts`: export the projection.
- `src/modules/desktop/DesktopHome.tsx`: `HomeSurface` now imported
  from work-board; new `operationsIntent` prop
  (`{ nonce, view, workHubView }`) applied by an effect — the nonce
  makes each dispatch a distinct apply even when it names the same
  surface.
- `src/app/App.tsx`: `homeOperationsIntent` state; the
  `altai:open-operations` listener routes agent mode to
  `desktopDestination: "home"` + the intent (announced "Home") and
  keeps the studio path unchanged; the intent is passed to
  `DesktopHome`.

## Out of scope

- The legacy `ProjectBoardPanel` and studio routing (untouched; cutover
  is stage 10).
- Any durable chat-side state, embedding of full projections inside
  the chat panel, or a new chat chrome surface (067 later PRs may add
  mini-app embeds on top of this routing).
- `altai:open-ai-surface` and other chat events.
