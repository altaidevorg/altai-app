# CP-08-28 — Budget policy + hard-stop enforcer

**Status:** in progress
**Backlog package:** 043 (second PR)
**Depends on:** CP-08-27 (package 043 ledger — `UsageRecord`, `UsageScope`, `SqliteUsageRepository`)

## Outcome

Closes the second half of the 043 gate — **"hard stops enforce"** — by introducing
budget policy rows and a tested enforcement seam that sums the usage ledger and
returns the canonical `ControlError::BudgetStopped` when consumption reaches a
limit. A `Budget` is a policy (`scope` + `meter` + `limit`); consumption is never
stored on the budget — it is derived from the immutable ledger, so there is a
single source of truth and no double-bookkeeping.

The `BudgetEnforcer::enforce(consumption_scope, meter)` is the enforcement
primitive: any caller that runs it gets a real hard stop. Wiring it onto the live
admission path (`DispatchEligibilityEngine` → `SingleWriterScheduler`) is a
follow-up, exactly as the ledger (CP-08-27) landed before any consumer.

## Rationale

A budget without the ledger it reads is policy with no teeth; the ledger without
a budget is audit with no stop. This PR pairs them so enforcement is real and
testable end-to-end: record usage, set a budget, enforce, observe `Ok` or
`BudgetStopped`. Consumption is summed within each governing budget's own scope
(a project budget spans every attempt/agent in that project), reusing the
`matches_scope` coverage rule from the ledger: a budget governs a consumption
when the consumption's scope matches the budget's scope (budget `Some` dims are
equality filters; the budget may be broader than the consumption).

## Scope (this PR)

- `altai-control-protocol/src/id.rs`: `BudgetId` (`bud_`).
- `altai-control-protocol/src/budget.rs`: `Budget { id, scope: UsageScope,
  meter: String, limit: u64, created_at_unix_seconds: u64 }`.
- `altai-control-plane/src/budget_repository.rs`: `BudgetError` (`Conflict`,
  `Internal`), `BudgetRepository` trait, `SqliteBudgetRepository` mirroring the
  usage/approval store (idempotent create, Conflict on divergent, insert-only).
  Table `control_plane_budgets (budget_id TEXT PRIMARY KEY, payload_json)`.
  Methods: `create`, `get`, `list_in_org(organization_id)`.
- `altai-control-plane/src/budget_enforcer.rs`: `BudgetEnforcer` holding
  `Arc<dyn UsageRepository>` + `Arc<dyn BudgetRepository>`;
  `enforce(&self, consumption: &UsageScope, meter: &str) -> Result<(),
  ControlError>` — for each governing budget (org match, meter match,
  `matches_scope(consumption, budget.scope)`), sum the ledger within
  `budget.scope` for that meter and return `BudgetStopped { scope }` when the
  total `>=` the limit. First exceeded budget wins.
- `usage_repository::matches_scope` promoted to `pub(crate)` for reuse.
- `lib.rs` exports in both crates.

## Out of scope (follow-up PRs)

- Wiring `DispatchBlocker::BudgetExhausted` into `DispatchEligibilityEngine`
  (onto the live `SingleWriterScheduler` admission path) and a transport route
  for creating budgets. No attempt is blocked by this PR; enforcement capability
  is delivered and tested, not yet invoked by the scheduler.

## Invariants

- Consumption is derived from the ledger; the budget stores only policy.
- A budget governs a consumption iff org matches and every budget `Some` dim
  equals the consumption's dim (the budget may be broader).
- A hard stop fires at `total >= limit` (fail-safe: at the limit, stop).
- Enforcement is org-isolated: a budget never sees another org's usage.
