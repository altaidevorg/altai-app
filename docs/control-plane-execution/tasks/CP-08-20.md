# CP-08-20 — Schedule backend seam

**Status:** in progress  
**Backlog package:** 036  
**Depends on:** CP-08-02 (package 034, AttemptExecutor)

## Outcome

Record exactly one schedule backend per attempt, immutably. An attempt binds to
exactly one `ScheduleBackend` (`NativeLocal` for the single-writer CP-07
scheduler; `Managed` realized later by the package-041 cron bridge), and that
binding is insert-only: rebinding the same backend is idempotent, a divergent
backend fails closed. This is the seam the cron bridge consumes — a managed
scheduler cannot register a second backend for an attempt the native scheduler
already owns.

## Rationale

The control plane has no concept of *which* scheduler owns an attempt. Package
041 will materialize a managed `cron` scheduler alongside the native one; without
a per-attempt backend record, both could drive the same attempt. This package
introduces the immutable one-per-attempt record now, ahead of the bridge, so the
"exactly one backend" invariant is enforceable by construction before a second
backend exists. It mirrors the established insert-only repositories
(`RunBindingRepository`, `ExecutionSnapshotRepository`): a new table keyed by
`attempt_id` PRIMARY KEY with no update path.

`Managed` is included even though only `NativeLocal` is realized today: the seam
exists specifically to keep two backends from colliding, so the second variant
is what makes the immutability contract meaningful and testable.

## Scope (this PR)

- Protocol: `ScheduleBackend` enum (`NativeLocal`, `Managed`, snake_case serde)
  and `ScheduleBackendBinding { attempt_id, backend, bound_at_unix_seconds }`.
- Control-plane: in-process `ScheduleBackendRepository` (`bind`, `get`) with
  `SqliteScheduleBackendRepository` over `control_plane_schedule_backend_bindings`.
- No transport route and no daemon wiring: like `ExecutionSnapshotRepository`,
  this lands as a library seam; a later package wires the scheduler to bind
  `NativeLocal` and the cron bridge (041) to attempt `Managed`.

## Invariants

- Exactly one backend per attempt: `attempt_id` PRIMARY KEY, insert-only, no
  update path in code.
- Idempotent: rebinding the same backend returns the stored binding unchanged.
- Fail-closed immutability: a divergent backend is rejected as `Conflict`; the
  first binding wins and is never overwritten.
- Durable: the binding survives reopening the SQLite store.
