# CP-08-23 — Routine cron materialization seam

**Status:** in progress
**Backlog package:** 041 (first PR)
**Depends on:** CP-08-21 / CP-08-22 (package 040, routine abstraction)

## Outcome

The first half of the scheduler materialization and cron bridge: an in-process
`RoutineMaterializer` that, given `now`, scans active routines and enqueues one
coalesced `Routine`-source wake for each whose current revision carries a
recurring cron trigger that has fired since its last materialized fire. The
existing single-writer scheduler then claims and dispatches that wake like any
other, so recurring work flows through the same dispatch path as manual wakes
without registering a second scheduler. This PR is the seam — no daemon driver
loop, no schedule-backend guard yet (follow-up).

## Rationale

Package 040 gave routines a durable, versioned contract and a command port but
no way to act on a recurring trigger. Package 041 bridges a revision into a wake
when its cron fires. The riskiest piece is cron due-evaluation; it is isolated
here as a pure, exhaustively-tested helper (`cron_due`) backed by the
battle-tested `cron` crate, then consumed by a thin materializer. This mirrors
how `SingleWriterScheduler` is an in-process `claim_if_eligible` without owning
the loop: the driver/tick and the native-vs-managed backend guard land in a
later package, after the materialization logic is proven in isolation.

## Scope (this PR)

- `cron_due.rs` (NEW, pure): `next_fire_after(expr, anchor) -> Option<u64>` and
  `is_due(expr, anchor, now) -> bool`. Accepts standard 5-field Unix cron by
  prepending a `0` seconds field (the `cron` crate requires a leading seconds
  field); 6/7-field expressions pass through. O(1) per routine (only the first
  fire after the anchor).
- `routine_repository.rs`: `RoutineRepository` gains `list_active`,
  `last_fired`, and `record_fire` over a new `control_plane_routine_fires`
  table (per-routine anchor).
- `routine_materializer.rs` (NEW): `RoutineMaterializer::materialize_due(now)`
  lists active routines, evaluates each recurring current revision for
  due-ness, enqueues an idempotent wake for the target work item, and records
  the fire. Event-triggered routines are skipped (not cron-driven). A malformed
  expression is skipped, not fatal.
- Deps: `cron = "0.12"`, `chrono = "0.4"` (already a workspace dep).
- No daemon wiring, no transport route, no scheduler changes.

## Invariants

- At most one wake is enqueued per due routine per tick; missed periods collapse
  to a single enqueue, not a replay (the anchor advances to the acted-on fire).
- Idempotent within a period: a second `materialize_due` at the same `now`
  enqueues nothing.
- A bad cron expression never aborts materialization of other routines.
- The dispatch path is unchanged: the materializer only enqueues wakes; the
  single-writer scheduler remains the sole claimer.
