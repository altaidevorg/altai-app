# CP-08-32 — Liveness monitor for stale attempts

**Status:** done
**Backlog package:** 044 (first PR)
**Depends on:** CP-08-07/08 (package 030 attempts), CP-07-06 (#740, package 023 recovery store)

## Outcome

First half of the 044 gate — **"Crash/restart recovery preserves ownership and
explainability"** — the liveness half. A `LivenessMonitor` detects attempts whose
owner has gone silent: an attempt in an owned state (`Claimed`, `Dispatched`,
`Running`) whose `updated_at_unix_seconds` has not advanced within the
staleness window is transitioned to `Lost`, and the reaped attempts are
returned so the caller can retain the trigger evidence (failure records,
dead-letters — package 023's store).

Ownership is preserved because the attempt row is never deleted or reassigned —
it terminates as `Lost` with its original `owner_agent_instance_id` intact, and
the recovery pass (next PR) creates a *new* attempt rather than resurrecting
the lost one. Explainability is preserved because the monitor returns exactly
what it reaped and when.

## Rationale

`AttemptState::Lost` and the `(Created|Claimed|Dispatched)→Lost` transitions
already exist in the state machine (package 030) — nothing reads liveness to
drive them. `updated_at_unix_seconds` advances on every transition, so
"no progress signal within the window" is a real staleness signal available
without new infrastructure (no heartbeat channel exists; adding one belongs to
the runtime that produces progress events).

`Created` is deliberately not monitored: nobody owns it yet, so there is no
owner to lose — losing a Created attempt is a dispatch problem, not a liveness
one. Terminal states cannot be stale by definition. The monitor is idempotent:
a reaped attempt leaves the owned states, so the next scan no longer sees it.

## Scope (this PR)

- `altai-control-plane/src/attempt_repository.rs`: add
  `list_in_state(state) -> Vec<Attempt>` to the trait and the SQLite
  implementation (payload decode + state filter — mirrors `list_pending`).
- `altai-control-plane/src/liveness_monitor.rs` (new): `LivenessMonitor` holding
  `Arc<dyn AttemptRepository>`.
  - `reap_stale(&self, now_unix_seconds: u64, stale_after_seconds: u64) ->
    Result<Vec<Attempt>, LivenessError>`.
  - For each attempt in `Claimed`, `Dispatched`, `Running` where
    `now - updated_at >= stale_after`, `transition` to `Lost` at `now`.
  - Returns the post-transition (Lost) attempts in a stable order (by id).
  - `LivenessError` wraps `AttemptError`.
- `lib.rs` exports. No protocol change.

## Out of scope (follow-up PRs)

- The recovery pass — requeueing lost work as fresh attempts with bounded
  retries via the package-023 store (CP-08-33).
- Heartbeat/progress-event production (belongs to the run runtime).
- Transport route / scheduler invocation of the monitor.

## Invariants

- Only owned non-terminal states are reaped (`Claimed`, `Dispatched`,
  `Running`); `Created` and terminal states are untouched.
- A reaped attempt keeps its identity and original owner; nothing is deleted.
- `reap_stale` is idempotent: reaped attempts leave the monitored states.
- The monitor mutates only via the validated `transition` path.
