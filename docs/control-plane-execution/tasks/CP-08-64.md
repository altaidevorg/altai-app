# CP-08-64 — External-object conflict resolution

- **Package:** 070 — ExternalObject model and GitHub adapter (PR 4)
- **Status:** in review
- **Depends on:** 060 (engine: #810), provider (#811)

## Outcome

A refused external-object overwrite can now be decided explicitly, in
both directions, and the decision is auditable. The store records what
was refused; a resolver picks `take_external` or `keep_local`; the
engine records the decision as an `ExternalSync` activity event under
`Actor::System`. This closes the package-070 gate's third clause —
conflict *resolution*, not just conflict *reporting*.

## Rationale

Neither direction rewrites content at resolution time, because the
existing machinery already carries both paths:

- **`TakeExternal`** flips the object's authority to `External`. The
  next sync then applies the provider's version through the normal
  update path — no special-case write, no content stashed at resolve
  time that could go stale.
- **`KeepLocal`** dismisses exactly the refused external content: the
  store keeps the refused hash as `declined_content_hash`, and an
  identical provider payload becomes `Unchanged` instead of
  re-conflicting. A *new* external hash still conflicts — the decision
  answers one divergence, not future ones.

Two distinct markers, not one: the hash a sync refused
(`refused_content_hash`, presenting state for a resolver) is not the
hash a user dismissed (`declined_content_hash`, a decision). Collapsing
them would auto-dismiss every first refusal and conflicts would never
be seen twice — visibility would die to save a field.

Resolution rules are strict on purpose: `TakeExternal` on an
already-external object and `KeepLocal` with nothing refused are
`InvalidResolution` errors, not quiet no-ops — a resolver that calls
them is working from stale state and should hear about it.

## Scope

- `altai-control-protocol/src/external.rs`:
  `ExternalObject` += `refused_content_hash` / `declined_content_hash`
  (`#[serde(default)]`, so payloads written before this PR decode
  unchanged; no table or schema-version change).
- `altai-control-plane/src/external_object_repository.rs`: the conflict
  branch persists the refused hash (local content and sync ordering
  untouched); the declined check quiets exactly the dismissed content;
  `ConflictResolution` + `resolve_conflict` +
  `ExternalObjectError::InvalidResolution`.
- `altai-control-plane/src/external_sync.rs`:
  `resolve_external_conflict` — store decision plus one audit event,
  standalone from the service because a resolution needs no provider.
- Desktop: `external_object_resolve_conflict` command
  (`modules/external_sync.rs`, validated resolution vocabulary,
  default local organization, real clock) + TS
  `ExternalObjectResolution` / `ExternalObjectStatus` types and
  binding. No UI in this PR — a resolver surface is later work.

## Verification

- `cargo test -p altai-control-plane` — 5 new store tests (refusal
  records the hash without touching local content; keep-local quiets
  exactly that content and a new hash re-conflicts; take-external flips
  authority and the next sync applies; the invalid-resolution states)
  plus one engine test (refuse → resolve keep-local → same content is
  `Unchanged`, with refusal and decision as two audit facts and nothing
  for the quieted run).
- `cargo test -p altai` (desktop, incl. 2 parse tests), clippy
  `--all-targets -D warnings` on protocol, control-plane and desktop.
- `pnpm exec tsc --noEmit`, `pnpm exec eslint` on the touched file.
