# CP-08-21 — Routine + revision contracts and repository

**Status:** in progress  
**Backlog package:** 040 (first of two PRs)  
**Depends on:** CP-07-05 (package 024, authenticated wake/checkout transport)

## Outcome

Introduce the `routines.*` abstraction: a versioned recurring or event-triggered
work definition. A `Routine` aggregate owns identity and lifecycle; its intent
lives in immutable, append-only `RoutineRevision` records and the aggregate
points at its current revision. Nothing here registers a scheduler — the
package-041 cron bridge materializes a revision into Wake/RoutineRun, and the
package-036 schedule-backend seam already enforces exactly one backend per
attempt — so this satisfies "versioned routine intent exists without registering
two schedulers."

## Rationale

The control plane has no concept of scheduled/recurring work. `RoutineId`,
`RoutineRevisionId`, and `RoutineRunId` typed IDs were reserved early, but no
`Routine` contract exists. Package 041 (cron bridge) needs a durable, versioned
routine intent to materialize; this package supplies the contract and the
append-only storage ahead of the bridge, mirroring how the agent profile
revision pattern (`AgentInstance` + immutable `AgentProfileRevision`) versions
intent. The second 040 PR (CP-08-22) adds the authenticated command port
(transport routes); this PR is the in-process contract + repository, like
`ExecutionSnapshotRepository` and `ScheduleBackendRepository`.

## Scope (this PR)

- Protocol (`altai-control-protocol/src/routine.rs`, NEW): `RoutineStatus`
  (`Active`/`Paused`/`Retired`), `RoutineTrigger` (`Recurring { cron_expression }`/
  `Event { source }`), `RoutineRevision` (immutable intent: id, routine_id,
  monotonic intent `revision`, trigger, `target_work_item_id`, created_at), and
  `Routine` aggregate (id, organization_id, `current_revision_id`, status,
  aggregate `revision`, created/updated).
- Control-plane (`routine_repository.rs`, NEW): `RoutineRepository` trait
  (`create`, `append_revision`, `get`, `get_revision`) with
  `SqliteRoutineRepository` over `control_plane_routines` +
  `control_plane_routine_revisions`. Append-only intent: each accepted revision
  becomes current and advances the aggregate revision; replay of the same
  revision id is idempotent.
- No transport route, no scheduler wiring.

## Invariants

- Intent is append-only and immutable: a `RoutineRevision` is never mutated once
  stored; `routine_revision_id` is the PRIMARY KEY.
- The aggregate `current_revision_id` only moves forward to a newly appended
  revision; the aggregate `revision` advances on each accepted append.
- Replaying the same revision id is idempotent (no double-advance).
- Create is idempotent for an identical routine and fails closed (`Conflict`)
  for a divergent routine under the same id.
- A revision may only be appended to a routine that exists (`NotFound`), and its
  `routine_id` must match (`Conflict`).
