# CP-08-45 — Desktop/Studio control-protocol adapter (embedded host)

**Status:** complete
**Backlog package:** 053 (Desktop/IDE/Studio/CLI adapters) — PR 2 of 3–4
**Depends on:** CP-08-36/37 (package 051 protocol + dispatcher), CP-08-43 (package 052 registry migration lifecycle), CP-08-44 (CLI adapter, first embedded host)

## Outcome

The Tauri desktop app — including its Studio window mode, which shares the
same command surface — is now an `EmbeddedHost` deployment of the versioned
control protocol. Two new Tauri commands, `control_protocol_negotiate` and
`control_protocol_execute`, frame `CapabilityNegotiationRequest` and
`ProtocolRequest<ProtocolCommand>` through the same `ProtocolDispatcher` the
deployed backend and the CLI serve, backed by the same workspace `work.db`.
Every alt-OS host family now embeds one dispatcher instead of re-implementing
command semantics.

## Rationale

CP-08-44 made the CLI the first embedded host and left Desktop/Studio as the
remaining in-repo host family for package 053's gate ("the same command
causes the same transition on every host"). The desktop's per-command store
opens already share CP-08-43's single migration lifecycle; the protocol host
reuses that same gate so a newer-schema database is refused before any
dispatcher is built — never piecemeal.

## Scope

- `modules/control_protocol.rs` (new): `ControlProtocolHost` — one dispatcher
  per workspace `work.db`, honest capabilities (`capabilities_from_wiring`:
  only `activity_audit` and `event_replay` advertised; unserved domains
  answer typed dispatcher errors), framing only, no domain logic. Two
  `#[tauri::command]`s delegate to it after workspace authorization.
- `WorkspaceRegistry` caches one `Arc<ControlProtocolHost>` per `work.db`
  (pattern: `migrated_work_dbs`); hosts are built only after
  `ensure_work_db_migrated` accepts the database, and failures are not
  cached so an updated database recovers without an app restart.
- Commands registered in `lib.rs` `generate_handler!`.
- Conformance tests mirror the CLI adapter's: migration-gated open serving
  `query_activity`, host reuse (`Arc::ptr_eq`), newer-schema refusal without
  caching, host-vs-reference-dispatcher parity on the same database
  (execute + negotiate), and unparsable-payload transport error.

## Out of scope

- Frontend consumers of the commands — Stage 6 product surfaces (packages
  061+) own projection/query UX; the command surface exists and is pinned.
- Serving domain commands beyond what the dispatcher already serves; typed
  dispatcher errors answer until a package adds serving.
- A cross-host conformance suite artifact — parity is pinned per host
  against a reference dispatcher on the same database.
