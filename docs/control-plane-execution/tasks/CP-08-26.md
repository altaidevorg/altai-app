# CP-08-26 — Approval transport (create + resolve routes)

**Status:** in progress
**Backlog package:** 042 (second PR)
**Depends on:** CP-08-25 (package 042 contract + immutable audit store)

## Outcome

Exposes the immutable-audit approval store over the authenticated loopback
transport. A bootstrap-authenticated caller can create an approval request and
record the immutable decision that resolves it, with the same idempotent /
fail-closed semantics as the routine routes: create is idempotent on replay and
`409`s a divergent same-id request; resolve is idempotent on an identical
re-decision, `409`s a divergent outcome, and `404`s an unknown approval.

This wires the governance contract (CP-08-25) to the wire but does not yet enact
a decision's effect — enqueuing an `ApprovalResult` wake and transitioning the
work item's execution phase land in a follow-up PR.

## Rationale

Package 042's gate is "decisions bind scope and payload revision; audit is
immutable." CP-08-25 delivered the durable contract and store in isolation; this
PR puts it behind the daemon's authenticated transport so a host or operator can
drive approvals without an in-process call. The resolve route binds the approval
id from the path and takes only the outcome + audit fields in the body, mirroring
how attempt finalization binds identity from its path — a client cannot forge the
target of its own decision.

## Scope (this PR)

- `transport.rs`: `ApprovalRepository` as a tenth `ApiState` field and tenth
  parameter to `router_with_control_repositories` (`None` in
  `router_with_all_repositories`).
- Routes: `POST /v1/approvals` (create) and
  `POST /v1/approvals/{approval_id}/decisions` (record_decision). Both require
  the bootstrap bearer.
- Resolve handler builds the `ApprovalDecision` from the path id +
  `ApprovalDecisionRequest` body (`outcome`, `decided_by`,
  `decided_at_unix_seconds`, `reason`); no client-supplied approval id.
- `From<ApprovalError>`: `NotFound` → 404 `approval_not_found`, `Conflict` → 409
  `approval_conflict`, `Internal` → 500 `approval_repository_unavailable`.
- `approvals()` accessor → 503 `approval_repository_unavailable`.
- `main.rs`: open `SqliteApprovalRepository` over `work.db` and pass `Some(..)`
  as the tenth repository.
- Four existing transport tests updated to pass the tenth `None` repository.
- No wake enqueue, no execution-phase mutation (follow-up PR).

## Invariants

- Both routes require the bootstrap bearer; an unauthenticated request is
  rejected before storage is touched.
- Create is idempotent on an identical approval and `409`s a divergent one.
- Resolve is first-writer-wins: an identical re-decision returns the resolved
  approval without re-advancing; a divergent outcome `409`s; an unknown approval
  `404`s.
- The approval id is authoritative from the path, not the body.
