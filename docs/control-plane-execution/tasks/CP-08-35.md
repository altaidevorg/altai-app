# CP-08-35 — Fail-closed repository scopes

**Status:** complete
**Backlog package:** 050 (second PR)
**Depends on:** CP-08-34 (050 PR 1 — workspace identity and reattachment)

## Outcome

Closes the second clause of the 050 gate — **"permissions and repository
scopes fail closed"** — and with it package 050. A `RepositoryScope` is an
explicit, org-scoped allowlist entry naming one repository URL the
organization has permitted. `WorkspaceScopeGate::permits` asks "may this
workspace operate on its repository?" and answers **deny unless an explicit
grant exists**: a workspace with no repository binding denies, a URL with no
grant row denies, and only a grant in the workspace's own organization
(resolved through its project) permits.

## Rationale

An allowlist is the honest shape of "fail closed": absence of a record is the
denying condition, so the store is insert-only with idempotent re-grants —
there is nothing to update and no revoke path yet (revocation is a governance
action that belongs with approval-backed policy, a later package). Grants are
per organization: two organizations may permit the same URL independently,
and a workspace's organization is derived from its project — never trusted
from the caller.

Like the budget and delivery gates, this is a check seam: the executors that
clone, fetch, and deliver through repositories (later workspace packages) are
required to ask; nothing here performs those actions.

## Scope (this PR)

- `altai-control-protocol/src/workspace_scope.rs` (new type):
  `RepositoryScope { organization_id, repository_url, granted_at_unix_seconds }`
  — no id; the grant *is* the (org, URL) pair.
- `altai-control-plane/src/repository_scope_repository.rs` (new):
  `RepositoryScopeRepository` trait + `SqliteRepositoryScopeRepository`
  (`control_plane_repository_scopes` table keyed `(organization_id,
  repository_url)`): `grant` (idempotent), `list_in_org`,
  `is_granted(&OrganizationId, &str)`.
- `altai-control-plane/src/workspace_scope_gate.rs` (new):
  `WorkspaceScopeGate { scopes: Arc<dyn RepositoryScopeRepository>, scopes_repo:
  Arc<dyn ScopeRepository> }` — `permits(&ProjectWorkspace) ->
  Result<ScopePermit, WorkspaceScopeError>` where `ScopePermit` is
  `Permitted { organization_id, repository_url }` or `Denied { reason }`
  (`WorkspaceNotBound`, `RepositoryNotGranted`), and errors wrap store/project
  read failures.
- `lib.rs` exports; protocol re-export.

## Out of scope (follow-up packages)

- Revocation (approval-backed governance action), wildcard/URL-pattern grants.
- Enforcement wiring in clone/fetch/delivery executors (later workspace packages).
- Transport route exposure.

## Invariants

- Absence of a grant denies; nothing is permitted by default.
- Grants are evaluated only against the workspace's own organization (via its
  project).
- The grant store is append-only; re-granting the same (org, URL) is
  idempotent.
- The gate never mutates; it reads and answers.
