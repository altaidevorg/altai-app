# CP-08-51 — Run Inspector timeline from the Work store's transition log

**Status:** complete
**Backlog package:** 063 (Runs hub and Run Inspector) — PR 1 of 2–3
**Depends on:** CP-08-50 (Work detail surface), package 060 (read-model
projections), the `work_events` log written by every WorkStore transition

## Outcome

The Run Inspector's first slice: a Work's timeline. The Work detail surface
now shows the Work store's own transition log — `created`, `state_changed`,
`attempt_started`, `attempt_run_bound`, `attempt_finished`, `accepted`,
`returned` — oldest first, each row a label plus the transition's typed
fact (from/to states, terminal phase, bound run id) and a relative time.

The insight that shaped this PR: the producer already existed. Every
`WorkStore` mutation appends to `work_events` in the same transaction as
the change, on every host — so the timeline can never disagree with the
state it explains, and no new event plumbing was needed. What was missing
was the read side, and that is all this PR adds.

## Rationale

Package 063's gate is "Timeline, transcript, approvals, evidence and
delivery are inspectable". Timeline first: it is the spine the other
slices attach to (a transcript belongs to an attempt, approvals and
evidence to a finish). Serving it from the store's log rather than a
frontend reconstruction keeps the package 060 rule — server projections,
not frontend store joins, answer operational queries.

Rows keep label and detail separate typed values; a transition without a
typed fact renders no detail slot, never placeholder text. Payload
parsing is defensive: an unparsable or mistyped payload degrades to the
event's label, and an unknown future kind falls back to its raw name —
the inspector never crashes on log rows it predates.

## Scope

- `altai-core work.rs`: `WorkEventRecord` + `WorkStore::list_work_events`
  (oldest first, bounded by `WORK_EVENTS_MAX = 500`); exported from the
  crate.
- `src-tauri/modules/work.rs`: `WorkEventDto` + `work_events` Tauri
  command (authorized workspace, same store-open gate as its siblings);
  registered in `lib.rs`.
- `packages/host-contract`: `WorkEvent` type beside `WorkAttempt`.
- `native.ts`: `workEvents(workId, workspacePath?)` with the
  optional-workspace-override pattern.
- `runTimelineProjection.ts`: `toWorkTimeline` — per-kind labels, detail
  extraction, defensive payload parsing, unknown-kind fallback.
- `WorkTimelineSection.tsx`: accessible ordered list — label, mono detail
  column, relative time.
- `WorkDetailPanel.tsx`: loads `workEvents` alongside the other supporting
  projections (fail-soft — an unavailable log degrades to no timeline
  section, never a failed detail); renders the timeline above the graph.
- `WORK_OS_PROGRAM_BACKLOG.md`: 063 → `in_progress`.

## Out of scope

- The Runs hub list surface — next 063 PR.
- Transcript, approvals, evidence and delivery inspection — later 063 PRs;
  the approval and evidence repositories already exist server-side.
- Opening a run from a timeline row or attempt row — needs the run
  transcript slice to point at.
- Serving the log through the control protocol's `QueryActivity` — the
  embedded host still fronts `control_plane_activity_events`; unifying the
  two event stores is a later, deliberate decision (they have different
  schemas and consumers).
