# CP-08-63 — GitHub issues provider

- **Package:** 070 — ExternalObject model and GitHub adapter (PR 3)
- **Status:** in review
- **Depends on:** 060 (engine: #810), GitHub connect (#795-era plumbing)

## Outcome

The desktop app can now run a real external-object sync: the
`external_sync_github_issues` command drives the PR 2 engine over a
GitHub issues provider and returns what happened. One connected token,
one repository, one command — the engine's idempotency, authority and
conflict rules apply unchanged because the provider only supplies
`ProviderObject`s.

## Rationale

The provider stays dumb on purpose; every rule it could get wrong is
either the engine's job or pinned by a test:

- **Identity**: `node_id` (immutable per issue) is the external id, not
  the human-facing `number` — renames and renumbering cannot fork a
  stored object's identity.
- **Canonical content**: the mapped `{title, state, body}` triple built
  through `serde_json::json!`, so key order is fixed by code and equal
  issues hash equal. A missing body maps to an explicit `null` field,
  never an absent one — "cleared the body" must not read as "unchanged".
- **One kind per mapping**: pull-request entries ride the issues
  endpoint with a `pull_request` marker; they are excluded rather than
  mislabeled as issues.
- **Bounded runs**: 100 per page, stop on a short page, hard cap of 50
  pages — a desktop sync terminates even against a very large repository.
- **Watermark shape**: the engine's unix-seconds watermark becomes the
  endpoint's `since` RFC 3339 value; round-tripping is tested.

The engine is synchronous, so the provider owns a private Tokio runtime
and blocks on the desktop GitHub client inside it; the command runs the
whole sync on `spawn_blocking`, never on a runtime worker.

## Scope

- `src-tauri/src/modules/github/external_sync.rs` (new):
  `GitHubIssueProvider` (implements `ExternalObjectProvider`),
  `IssueRaw` mapping with PR exclusion, ISO↔unix watermark helpers,
  bounded pagination, and the `external_sync_github_issues` Tauri
  command (token via the OS secret store, default local organization,
  real clock, camelCase report DTO).
- `src-tauri/src/modules/github/mod.rs`, `src-tauri/src/lib.rs`:
  module and command registration.
- `src/modules/ai/lib/native.ts`: `ExternalSyncReport` /
  `ExternalSyncConflict` types and the `externalSyncGithubIssues`
  binding. No UI in this PR — sync outcomes surface through the
  control-plane activity stream the audit feed already queries.

## Notes

The desktop audit feed reads the work-store journal, so the
`ExternalSync` activity events land via the control-protocol activity
query, not the AuditPanel — documented here rather than claimed
otherwise. Conflict *resolution* (an explicit action on a refused
overwrite) is the remaining package-070 slice.
