# CP-08-61 — ExternalObject model and durable storage

- **Package:** 070 — ExternalObject model and GitHub adapter (PR 1)
- **Status:** in review
- **Depends on:** 051, 060

## Outcome

`work.db` now has a durable external-object family: one row per
provider-owned object, keyed by `(integration, external_id)`, with
idempotent upsert semantics decided by an explicit per-object authority
rule. The protocol crate carries the contracts
(`ExternalObject`, `ExternalAuthority`); the control-plane crate owns
the SQLite repository. No network I/O anywhere in this PR.

## Rationale

Package 070's gate is "idempotent sync, explicit authority and conflict
resolution". All three are *storage* decisions before they are adapter
decisions: a sync engine can only be idempotent if the store tells it
"this payload is already here", and conflicts can only be resolved
consistently if the winning side is recorded on the object rather than
implied by write order.

The primitives were already staged on the wire — `ExternalObjectId`
(`ext_…`), `Actor::External`, `EventKind::ExternalSync` — so PR 1 fills
in the model and the store:

- **Identity**: the provider's immutable id (`external_id`), never the
  mutable number or title; the upsert key is
  `(integration, external_id)`, so the same provider id under two
  integrations is two objects and a re-synced object keeps its local
  `ExternalObjectId` even when the caller mints a fresh one.
- **Idempotency**: the adapter maps a provider payload to a
  `content_hash`; an upsert with an equal hash is `Unchanged` — no
  write, no event, safe to replay.
- **Authority**: a changed hash applies when authority is `External`
  (provider is the source of truth) and is *refused* with a
  `Conflict` outcome carrying both hashes when it is `Local` — the
  stored content is left untouched for explicit resolution.
- **Linking**: `link_work_item` is explicit state, not a side effect of
  sync; an unlinked object stays synced.

## Scope

- `src-tauri/crates/altai-control-protocol/src/external.rs` (new):
  `ExternalObject`, `ExternalAuthority`; registered and re-exported in
  the crate root.
- `src-tauri/crates/altai-control-plane/src/external_object_repository.rs`
  (new): `ExternalObjectRepository` trait + `SqliteExternalObjectRepository`
  (`upsert`, `get`, `find`, `list_by_integration`, `link_work_item`);
  `ExternalSyncOutcome`; 6 tests covering insert/replay idempotency,
  authority-driven apply and refusal, per-integration keying,
  organization scoping, and explicit linking.
- `src-tauri/crates/altai-control-plane/src/local_migration.rs`: the
  repository joins the explicit schema-owner list; semantic lifecycle
  version 1 → 2; the table-family test now expects
  `control_plane_external_objects`.

## Out of scope

- The GitHub adapter itself (fetch, mapping to `content_hash`,
  sync windows) — package 070 PR 2.
- `ExternalSync` activity-event emission on `Updated`/`Inserted` — the
  sync service owns event writes, not the repository (matching the
  routine repository, which also does not cross-write events).
- Conflict *resolution flows* (UI or command that decides a `Conflict`
  outcome) — lands with the adapter once real conflicts can occur.
