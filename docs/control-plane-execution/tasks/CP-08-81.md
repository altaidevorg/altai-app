# CP-08-81 — Stand up the Paperclip downstream

- **Package:** 080 — Paperclip downstream/codebase (PR 2)
- **Status:** in review
- **Depends on:** CP-08-80 (#829, the charter)

## Outcome

The organization-owned downstream exists, exactly as the charter §2
binds it:

- **[`altaidevorg/paperclip`](https://github.com/altaidevorg/paperclip)**
  (private until the security review passes), `master` = upstream base
  `f0e6c0f` **plus root policy files only** — no adopted module is
  touched (commit `e7536aa9`).
- **History preserved:** 3,597 commits and 1,155 tags reachable from
  the base, pushed unmodified; upstream master's post-base commits are
  deliberately absent — advancing the base is a reviewed sync PR, not
  a standing mirror.
- **Policy files at the root:** `UPSTREAM_BASE.md` (base SHA, sync
  policy — update in the same PR as any sync), `DOWNSTREAM.md` (the
  binding rules, pointing at the charter), `SECURITY_REVIEW.md` (the
  §2.8 checklist, recorded as **unpassed**: nothing is exposed beyond
  localhost until it is).
- `upstream` remote set on the downstream; license (MIT) and notices
  carried through by the unmodified history.

In `altai-app`, the charter's §6 becomes the stand-up record and the
queue advances to the §4 acceptance spike.

## Rationale

- **Base-plus-policy, nothing else.** The charter's obligation set is
  reviewable precisely because the downstream's first state is
  auditable in one sentence: upstream base + three policy files.
- **No moving mirror.** Upstream master has already moved past
  `f0e6c0f`; the downstream intentionally does not track it. "Sync
  through PRs, never an unreviewed moving branch" is enforced by
  construction, not convention.
