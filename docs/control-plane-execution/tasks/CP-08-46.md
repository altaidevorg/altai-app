# CP-08-46 — Transport wire parity and host-adapter package closure

**Status:** complete
**Backlog package:** 053 (Desktop/IDE/Studio/CLI adapters) — PR 3 of 3
**Depends on:** CP-08-36/37 (package 051), CP-08-38/43 (package 052), CP-08-44 (CLI host), CP-08-45 (Desktop/Studio host)

## Outcome

Package 053's gate — "the same command causes the same transition on every
host" — now has wire-level evidence at every link. The deployed axum
transport's HTTP bytes for `/v1/protocol/negotiate` and
`/v1/protocol/commands` are pinned equal to the shared dispatcher's values,
which CP-08-44 and CP-08-45 already pinned equal to the CLI and desktop
hosts' framed responses. The chain is closed transitively: transport ==
dispatcher == every embedded host.

Alongside the parity pin, a second test pins the transport's error
discipline: an unwired capability answers HTTP 200 with a typed
`PolicyDenied` error inside the protocol envelope, keeping the HTTP status
reserved for transport issues — and the protocol routes stay behind the
bootstrap bearer guard.

The backlog is reconciled to reality: packages 051, 052, 053, 060 and 071
had all shipped their planned PRs without their rows being closed. All five
are now `accepted` with evidence PRs, and the stale immediate execution
queue (still listing CP-08-36 through CP-08-40) is refreshed to the next
dependency-satisfied work: package 061 (operations shell), then 062 (work
board).

## Rationale

Per-host parity tests compare each host to a reference dispatcher, but the
deployed transport's JSON framing had never been compared to anything — the
handler wraps the dispatcher call, yet nothing pinned that the HTTP body
equals the embedded hosts' values byte-for-byte at the JSON layer. Closing
that gap is the last untested link in package 053's gate. The backlog drift
is the same class of debt the task queue has repeatedly hit: docs lag
behind merged code, so the "next task" the backlog names is wrong until
reconciled against git history.
