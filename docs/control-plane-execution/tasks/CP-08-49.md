# CP-08-49 — Work board projection with distinct status, phase, attention

**Status:** complete
**Backlog package:** 062 (Work board/list/detail/graph) — PR 1 of 2–3
**Depends on:** CP-08-47/48 (operations shell), package 060 (read-model
projections: `work_list`, `work_attempts`, `work_inbox_list`)

## Outcome

The Work OS has its first board surface. Home's right pane — previously a
flat list whose execution-phase field was a hardcoded `"—"` — is now a board
of Work columns by status, each card carrying its latest attempt's phase and
its inbox attention as separate chips.

The gate's invariant — status, execution phase, and attention remain
distinct — is enforced in the projection's types, not just its rendering:
`WorkBoardRow` carries `status: WorkState`, `executionPhase:
WorkAttemptPhase | null`, and `attention: WorkInboxKind | null` as three
typed fields. Absent axes are `null`, never placeholder text, because the
axes move independently: a backlog item has no attempt; a running attempt on
in-review Work is not the same thing as review attention.

## Rationale

The three axes come from three server projections (package 060's answer to
"server projections, not frontend store joins, answer operational
queries"): Work state from `work_list`, phase from `work_attempts`, attention
from `work_inbox_list`. The board composes them client-side without ever
folding them together. Attention selection when several inbox conditions
compete for one Work uses a fixed priority (approval > review_required >
failed_attempt > blocked > question) so the card is deterministic rather
than arrival-ordered.

## Scope

- `src/modules/work-board/lib/workBoardProjection.ts`: `latestAttemptByWork`
  (highest attempt number, ties on updated time), `attentionByWork`
  (priority order), `toWorkBoardRow`, `projectWorkBoard` (newest-first),
  `ATTENTION_PRIORITY`, `BOARD_COLUMNS`.
- `src/modules/work-board/WorkBoard.tsx`: presentational board — status
  columns, per-card phase dot + label, attention chip, updated label,
  empty/error/loading states.
- `DesktopHome.tsx`: right pane swaps `WorkList` for `WorkBoard`; refresh
  now also fetches attempts per Work (failures degrade to no phase, they do
  not fail the board); `toHomeWorkRow` removed (orphaned — the board
  replaces its purpose).
- `native.ts`: `workAttempts` gains an optional `workspacePath` override,
  matching `workInboxList`, so Home queries the workspace it renders.
- `WORK_OS_PROGRAM_BACKLOG.md`: 062 → `in_progress`.

- Attempt timeline beyond the latest phase — the Runs hub (063) owns
