# CP-08-78 — The wiring: a real Gmail client and the account sync command

- **Package:** 074 — Full Gmail multi-account adapter (PR 3, closes the gate)
- **Status:** in review
- **Depends on:** CP-08-76 (#825), CP-08-77 (#826), 070 (#809–#812)

## Outcome

The Gmail adapter is live end to end. The gate's three sentences are
now three shipped things:

- **Account isolation** (CP-08-76 + this PR's commands): accounts are
  connected, listed, and disconnected by identity; `gmail_sync_account`
  runs the engine through `ExternalSyncService::for_account`, so objects
  carry the account and the sync window is that account's alone.
- **Scoped credentials**: the token lives in platform secret storage
  addressed by CP-08-76's `(plugin, account, name)` scope — the desktop
  fronting keeps the scope encoding in one place (`gmail/credentials.rs`);
  the wrong scope finds nothing, it does not find the neighbor.
  Disconnect removes exactly one account's credential and keeps the
  account row, so synced history stays attributable and reconnect reuses
  the identity.
- **Idempotent thread/message sync** (CP-08-77's mapping + this PR's
  client): `GmailHttpClient` lists bounded pages through the SSRF-safe
  module HTTP client, fetches the metadata of everything listed, and
  hands raw entries to the already-proven mapping — equal mailbox
  entries hash equal, so an unchanged entry never writes.

## Rationale

- **List, then enrich, never half-enrich.** Gmail's list endpoints
  answer ids only, so the client fetches metadata per entry. Everything
  listed is enriched; nothing listed is silently dropped. Entries Gmail
  reports gone between list and get (404/410) are skips, not failures —
  a mailbox that changed mid-run is normal. The page bound (50 pages ≈
  5 000 entries per run per kind) mirrors 070's GitHub bound: a desktop
  sync must terminate even against a very large mailbox.
- **Fail closed without a credential.** The sync command resolves the
  account row, reads the token through the scoped store, and refuses —
  "Gmail account is not connected" — before any request: an
  unauthenticated sync is never attempted, and an unknown account is
  never guessed.
- **Functions, not a trait impl, for the platform fronting.** The
  platform secret store is fallible and that failure must reach the
  command boundary; CP-08-76's `AccountCredentialStore` has infallible
  `put`/`remove` with nowhere honest to put a keyring error. The trait
  remains the contract for hosts and worker brokers with infallible
  stores; the scope encoding lives once, in `gmail/credentials.rs`.
- **Everything SQLite on a blocking thread.** Each command's repository
  opens and the engine run sit inside `spawn_blocking`, mirroring the
  GitHub adapter — the client's private Tokio runtime never shares an
  async worker with blocking work.

## Scope

- `src-tauri/src/modules/gmail/external_sync.rs`: `GmailHttpClient`
  (private runtime, `list_url`/`metadata_url` builders, page envelopes,
  404/410-tolerant metadata fetch) implementing `GmailClient`; the
  module's `#![allow(dead_code)]` is gone — the commands are the
  consumers it was waiting for; 2 client tests.
- `src-tauri/src/modules/gmail/credentials.rs` (new): scope encoding
  (`account-credential::{plugin}::{name}` service, account id address)
  over `secrets::{get,set,delete}_secret`; 1 test.
- `src-tauri/src/modules/gmail/commands.rs` (new):
  `gmail_connect_account`, `gmail_accounts_list`,
  `gmail_disconnect_account`, `gmail_sync_account` + DTOs; registered
  in `lib.rs`.
- `src/modules/ai/lib/native.ts`: `GmailAccount` type and the four
  bindings; the sync report reuses `ExternalSyncReport`.
