**[`altaidevorg/paperclip` PR
#11](https://github.com/altaidevorg/paperclip/pull/11)** —
`packages/adapters/altai-host`, registering as an **external adapter
plugin** under the new type `altai_host`:

- **Registration without registry edits.** The package entry exports
  `createServerAdapter()` — the exact contract

## Downstream CI bring-up (first PR on the repo)

PR #11 was the first PR the downstream ever ran, and it surfaced three
runner-class gaps between the adopted CI's assumptions and this org's
private-repo reality — each fixed on `master` as a policy adaptation
with the causal evidence in the commit message:

- `1c7df7bf` — the review workflow's dependency-review gate needs
  GitHub Advanced Security (absent on private repos without a license)
  and its bot gates need the upstream commitperclip app (not installed
  here); both failed hard on every PR, structurally. The steps now skip
  or report-only when the upstream capability is missing, preserving
  upstream behavior exactly when it exists.
- `16744c9b` — private-repo standard runners are 2-core/7 GB: the root
  `tsc` program OOMs at Node's ~2 GB default heap (verified locally
  against `master` without the PR — content-independent), and the
  P1–P7 smoke-lab e2e scenario costs ~55 s/scenario there against a
  240 s budget tuned on 4-core public runners. The typecheck lane pins
  a 4096 MB heap; the scenario budget doubles to 480 s.

Both hunks are commented in-place and will surface in any upstream
sync diff.

Final CI (after the master adaptations rode in): 22 checks SUCCESS,
1 SKIPPED, 0 failures — including all five serialized server shards
(one shard needed two runner-flake reruns, same code passing across
rounds), the typecheck lane under the pinned heap, and the 480 s
smoke-lab e2e. Merged as `9951d155`.
