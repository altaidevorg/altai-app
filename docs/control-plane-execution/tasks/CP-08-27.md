# CP-08-27 — Usage ledger contract + insert-only store

**Status:** in progress
**Backlog package:** 043 (first PR)
**Depends on:** CP-08-18/CP-08-19 (package 035 — attempt finalization, attribution IDs)

## Outcome

Delivers the durable, immutable usage/cost ledger: an append-only record of
metered consumption attributed by organization, project, agent, work item and
attempt. This is package 043's first half — "Cost attributed by
org/project/agent/work/attempt" — and the read source the budget layer (a later
PR) will sum to enforce hard stops. Nothing here sets a limit or stops
anything; this is the immutable audit seam, mirroring how package 042's
approval store (CP-08-25) landed the contract before CP-08-26 wired transport.

## Rationale

The 043 gate combines attribution and enforcement in one sentence. Splitting
them keeps each PR surgical and testable, exactly as 040/041/042 each shipped a
contract+store PR before its transport/wiring PR. A usage record is the atomic
unit of the ledger: one named meter (`"input_tokens"`, `"compute_seconds"`,
…) consumed by one attributed scope at one instant. Flat one-record-per-meter
rows are the natural append-only shape and make the future budget rollup a
straightforward filtered sum, with no speculative token-specific schema.

`UsageScope` doubles as both a record's attribution and the dimension a budget
will govern, so it is defined once in the protocol crate alongside the record.
`organization_id` is always required (the isolation/policy/budget boundary;
CONTEXT invariant: one identity per concept).

## Scope (this PR)

- `altai-control-protocol/src/id.rs`: `UsageRecordId` (`usage_`).
- `altai-control-protocol/src/usage.rs`: `UsageScope` (org + optional
  project/agent_instance/work_item/attempt) and `UsageRecord`
  (`id, scope, meter: String, amount: u64, recorded_at_unix_seconds`).
- `altai-control-plane/src/usage_repository.rs`: `UsageError`
  (`Conflict`, `Internal` — `get` returns `Option`, no `NotFound` needed),
  `UsageRepository` trait, and
  `SqliteUsageRepository` (`Mutex<Connection>`, single-writer) mirroring
  `approval_repository.rs`.
  - Table `control_plane_usage_records (usage_record_id TEXT PRIMARY KEY,
    payload_json TEXT NOT NULL)`.
  - `record`: idempotent on an identical re-record; `Conflict` on a divergent
    same-id record (PRIMARY KEY + ON CONFLICT DO NOTHING, then compare).
  - `get(id)`: `Option<UsageRecord>`.
  - `list_in_scope(scope)`: records matching every `Some` dim of the scope
    (set dims are equality filters; `None` dims are wildcards). `organization_id`
    is always an equality filter.
- `lib.rs` exports in both crates.

## Out of scope (follow-up PRs)

- Budget policy (limit + consumed aggregate + scope), its store, and the
  hard-stop enforcement that emits `ControlError::BudgetStopped` /
  `EventKind::BudgetEvent`. No limit, no sum-total aggregate method, no
  transport route.

## Invariants

- The ledger is append-only: a recorded fact is never edited or deleted.
- `record` is idempotent on identical replay and never advances anything.
- A divergent same-id record is rejected (`Conflict`); the audit never
  contradicts itself.
- `list_in_scope` isolates by `organization_id`; no cross-org read.
