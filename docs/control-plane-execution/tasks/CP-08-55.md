# CP-08-55 — Agents admin surface

**Status:** complete
**Backlog package:** 064 (Agents, org chart and profile administration) —
PR 2 of 2, completing the package
**Depends on:** CP-08-54 (embedded agent registry and `agent_*` commands,
#802)

## Outcome

The registry CP-08-54 made durable is now administrable. Home's right
pane becomes a two-surface pane — **Work | Agents** (the established
`SurfaceTabs`) — and the Agents surface administers the workspace's
registry:

- **Registry rows**: name, lifecycle status (dot + label), and the
  resolved reporting line ("Reports to X" / "No reporting line").
- **Lifecycle actions are command-driven**: Pause / Resume / Terminate
  each call `agent_transition`; Terminate takes a two-step inline
  confirm. Which actions a row offers is derived from the store's rules
  (terminated is final) in one place — the projection — not per button.
- **Reporting moves**: a per-row "Reports to" select calls
  `agent_set_reporting`; the create form offers the same manager
  options. The store's rejections (org-chart cycles, terminal agents,
  missing managers) surface as inline errors in agent vocabulary — the
  shared Work-shaped store error text is translated by the projection.
- **Registration**: a name + optional manager creates agents via
  `agent_create`.

With this, package 064's gate is met: lifecycle and reporting mutations
use control-plane commands, and the embedded host's registry has an
administration surface in the Work OS Home.

## Rationale

Mutations never edit local state as if it were the registry — every
action calls the store command and reloads, so the surface cannot drift
from `work.db`. The "agents" desktop destination still renders the chat
panel; per the program's cutover rule, repurposing a live legacy surface
waits for stage 10 — so the admin surface mounts in Home beside the
other Work OS surfaces, like packages 062–063 did. Action legality lives
in the projection because two surfaces (row buttons and manager options)
must agree with the store's rules without duplicating them.

## Scope

- `work-board/lib/agentsAdminProjection.ts` (+ tests): rows with status
  labels, resolved manager names, `canPause`/`canResume`/`canTerminate`;
  name-ordered projection with id map; manager options excluding self;
  store-error translation.

  actions with inline confirm, reporting selects, inline action errors,
  empty state.
- `DesktopHome.tsx`: right pane gains a Work | Agents `SurfaceTabs`
  switcher; opening Work (board row, run, detail link) returns to the
  Work surface; workspace change resets both surface and selection.
- `work-board/index.ts`: export `AgentsPanel`.
- `WORK_OS_PROGRAM_BACKLOG.md`: 064 → `accepted` (#802, #803); queue
  moves to package 065; dashboard Overall 20→21%, Product/UX 11→13%.

## Out of scope

- Repurposing the desktop "agents" navigation destination — it renders
  the chat panel today; cutover is stage 10.
- Agent profiles beyond identity (models, permissions, credentials) —
  those contracts belong to later packages.
- Backend registry sync — the embedded registry is its own authority
  until a cutover package decides otherwise.
