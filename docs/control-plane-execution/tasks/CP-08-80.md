# CP-08-80 — Paperclip downstream charter

- **Package:** 080 — Paperclip downstream/codebase (PR 1)
- **Status:** in review
- **Depends on:** DEC-001 (2026-08-13); 034, 060 accepted

## Outcome

The organization-owned downstream DEC-001 authorized now has its
charter: `PAPERCLIP_DOWNSTREAM_CHARTER.md`. It records the upstream
identity (`paperclipai/paperclip`, MIT, base SHA `f0e6c0f` verified
against the upstream commit), the binding downstream policy
(org-owned repo with `upstream` remote; license/notices/history
preserved; `UPSTREAM_BASE.md`; ALTAI changes in named adapters; sync by
reviewed PR only; upstream + conformance tests; SBOM/provenance;
security review before anything leaves localhost), and the concrete
module selection through adapter boundaries — every adopted module is
pinned to an ALTAI contract that already ships (010–012 identities,
042 approvals, 043 budgets, 060 activity, 070/074 external objects,
071–073 plugin workers), with execution adapters and the desktop
storage layer explicitly **Replace**, and the UI explicitly
**Reference only**.

"Study does not count as shipped": the charter names real modules at
the pinned revision and the boundary each rides; §4 restates the
acceptance spike against shipped contracts (dispatch one ALTAI Work to
a local host over 051/052; idempotent reconnect; projection reaches
Review); §5 fences what the charter does not authorize (no Paperclip
source into Apache artifacts from the charter alone; nothing here
unblocks 082's AGPL gate).

## Rationale

- **The decision existed; the mechanism did not.** DEC-001 and the
  parent adoption plan name the downstream in one sentence each. A
  track whose gate is "preserve license/history/base SHA" needs those
  obligations written where the standing-up PR can be reviewed against
  them — before the first byte of upstream code is mirrored.
- **Boundaries are contracts that already shipped.** 051/052 made the
  protocol versioned and conformance-tested; that line is what makes
  "adopt behind a boundary" enforceable rather than aspirational, and
  it is why the charter can pin each module to a package number.
- **Replace rows are as binding as adopt rows.** Naming what ALTAI does
  not take (execution adapters, desktop storage, UI code) is what keeps
  the downstream from becoming a second product.
