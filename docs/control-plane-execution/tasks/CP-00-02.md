## Current relevant code facts

### Rust workspace structure

`src-tauri/Cargo.toml` (lines 10–17) defines workspace members:
```text
crates/altai-core
crates/altai-agent-service
crates/altai-collaboration
crates/altai-protocol
crates/altai-cli
```

The future `altai-control-plane` and `altai-control-protocol` crates do not
exist yet. The architecture test must:
1. Define what modules may not be imported by `altai-agent-service`.
2. Initially pass because the forbidden modules don't exist yet.
3. Be structured so that adding `altai-control-plane` as a dependency of
   `altai-agent-service` would trigger a test failure.

### Frontend module structure

`src/modules/` contains:
- `orchestration/` — will be removed/replaced
- `ai/` — will be narrowed
- `github/` — will be narrowed
- `source-control/` — stays

Section 12.2 states architecture tests must fail when:
- an Operations component imports a legacy assignment, automation, notification,
  todo, or orchestration mutation store;
- an AI chat component imports Work/Routine lifecycle mutations;
- a GitHub component starts IsanAgent or transitions Work directly;
- a renderer contains claim, lease, schedule, retry, or recovery loops.

### Implementation approach

Since Operations components do not exist yet, the TypeScript test should:
1. Define the forbidden import rules as data.
2. Scan the `src/modules/` tree for violations.
3. Initially pass because no Operations module exists yet.
4. Include a self-test that proves a violation would be detected.
