# CP-08-47 — Operations context store and control-plane health probe

**Status:** complete
**Backlog package:** 061 (Operations shell and context switcher) — PR 1 of 2
**Depends on:** CP-08-45 (desktop control-protocol commands), CP-08-43 (migration lifecycle)

## Outcome

The operations shell now has one explicit context store. A zustand store
(`operationsContextStore`) holds the connection state machine —
`offline | connecting | degraded | healthy` — plus the workspace it describes
and the negotiated host identity (deployment mode, protocol version). A
`DesktopHome` status line renders that state for the open workspace, so
"can the control plane serve this workspace?" is answered visibly instead of
being inferred from whether individual lists load.

Health is probed through the same `control_protocol_negotiate` command every
host serves (CP-08-45): a compatible negotiation is `healthy`; a command
error (e.g. a `work.db` schema newer than this build) or an incompatible
negotiation is `degraded` with the reason retained; no open workspace is
`offline`. Stale probes are dropped by workspace path, so a slow result can
never speak for a workspace that has since closed or switched.

## Rationale

Package 061's gate — health/offline/org/project context states are explicit —
starts with health: every later operations surface (board, runs hub,
governance) mounts under a shell that already knows whether the control plane
is serving. Reusing the protocol negotiate command as the probe (rather than
a bespoke ping) means "healthy" is defined by the same dispatcher parity the
host conformance work pinned, and the classification costs one cheap command
against a cached per-`work.db` host.

## Scope

- `src/modules/operations/lib/operationsHealth.ts` — negotiation params
  (client `altai-desktop`, protocol 1.0, no required capabilities in PR 1),
  the injectable `probeOperationsHealth` classifier, and the
  `control_protocol_negotiate` binding.
- `src/modules/operations/store/operationsContextStore.ts` — zustand store;
  `setWorkspace` enters offline/connecting and voids the previous
  workspace's negotiation; `applyHealth` folds one probe in, ignoring
  results from a workspace that is no longer open.
- `src/modules/operations/OperationsStatusBar.tsx` + mount in
  `DesktopHome.tsx` headers — one status line (state dot, connection text,
  host identity when healthy, reason when degraded, manual recheck).
- `WORK_OS_PROGRAM_BACKLOG.md`: package 061 → `in_progress`.
