# CP-08-48 — Shell-chrome context indicator and package 061 closure

**Status:** complete
**Backlog package:** 061 (Operations shell and context switcher) — PR 2 of 2
**Depends on:** CP-08-47 (operations context store and health probe)

## Outcome

Package 061's gate — health/offline/org/project context states are explicit —
is closed at the shell chrome, not just the Home surface:

- The statusbar now carries a control-plane badge (dot + state, click to
  re-probe, tooltip with the reason, serving host, protocol version, and
  scope). It is visible on every destination, so "is the control plane
  serving this workspace?" is answered app-wide.
- The context store gains an explicit `scope`: the deployment's
  organization/project context. The embedded desktop host serves no
  org/project projections over the protocol yet (it wires only
  `activity_audit` and `event_replay`), so the honest scope today is
  **workspace-local** — one local organization, the open workspace as the
  project — and the badge labels it as such rather than fabricating
  protocol-sourced org IDs.
- The store's single driver moved to the app root (`useOperationsProbe`):
  one probe per workspace change, owned by the shell instead of whichever
  surface happens to be mounted. The DesktopHome line and the badge are
  read-only consumers.

## Rationale

PR 1 answered health for the Home surface only, and the driver lived inside
`DesktopHome` — an always-mounted-but-CSS-hidden panel, meaning studio-mode
layouts without the desktop panel would never probe. Moving the driver to the
app root makes the context lifecycle independent of surface mounting, and the
statusbar placement makes the state visible wherever the user is. The
org/project half of the gate cannot be protocol-sourced today: the versioned
protocol's command set is negotiate/query-activity/replay-events, so an
explicit local scope with its limitation stated is the truthful answer, and
the store type documents where protocol-sourced scope replaces it.
