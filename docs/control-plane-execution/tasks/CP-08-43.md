# CP-08-43 — App lifecycle integration of the local migration runner

**Status:** complete
**Package:** 052 (local migration runner and lifecycle) — PR 2 of 2
**Depends on:** CP-08-38 (local `work.db` migration runner)

## Outcome

The desktop app now brings a workspace's `work.db` to the current Work OS
schema through one lifecycle gate. Every Work IPC command passes through
`WorkspaceRegistry::ensure_work_db_migrated` before `WorkStore::open`, so the
core store and the control-plane schema owners are initialized together — or
refused together — instead of depending on which repository happens to open
first. This closes the follow-up CP-08-38 left open when the CP-08-39 task
number was allocated to package 060.

## Rationale

CP-08-38 shipped `LocalMigrationRunner` with no production consumer: the
desktop opened only `altai_core::WorkStore` per command, leaving the
control-plane table families to appear whenever their first consumer landed.
Package 052's gate — "migrations and app lifecycle share one tested local
semantic model" — requires the runner to sit on the app's open path, not in a
side entry point. The registry owns per-run workspace lifecycle state already
(authorized roots, opened grants, canonical cache), so the once-per-run
migration cache lives beside them.

## Scope

- `WorkspaceRegistry::ensure_work_db_migrated(&database)` (modules/workspace.rs):
  runs `LocalMigrationRunner::migrate` once per app run per database, caches
  success only, and maps `UnsupportedSchema` to an actionable user-facing
  message (update Altai to open this workspace).
- `open_store` (modules/work.rs) consults the gate before `WorkStore::open`;
  all 14 Work IPC command call sites thread the registry through.
- Tests pin the lifecycle contract end to end: a fresh workspace migrates and
  opens idempotently within a run; a newer-schema database fails closed with
  the typed message and leaves no adapter DDL behind; migration success is
  cached per run; refusals are never cached so an updated database recovers
  without an app restart.

## Out of scope

- Wiring `altai-cli` (`main.rs`, `serve/work.rs`) into the runner: the CLI
  does not depend on `altai-control-plane` and its surfaces open only the
  core `WorkStore` schema family today. The CLI adopts the same gate in the
  package that first gives it a control-plane consumer.
