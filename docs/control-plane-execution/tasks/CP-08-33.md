# CP-08-33 — Recovery pass for lost attempts

**Status:** done
**Backlog package:** 044 (second PR)
**Depends on:** CP-08-32 (liveness monitor), CP-07-06 (#740, package 023 recovery store), CP-08-07/08 (package 030 attempts)

## Outcome

Second half of the 044 gate — **"Crash/restart recovery preserves ownership and
explainability"** — the recovery half. `RecoveryService::recover_lost` consumes
a reaped (Lost) attempt: it records the failure in the package-023 recovery
store (which counts retries **per work item** and dead-letters past
`max_retries`), and — while retries remain — creates a *fresh* attempt in
`Created` for the same work item, owner, and profile revision so the scheduler
can redispatch it. Past the bound it returns the dead-letter record and creates
nothing.

This closes package 044: the monitor (CP-08-32) detects silence; this pass
responds with bounded, explainable requeueing.

## Rationale

Ownership is preserved because the lost attempt is never reopened or reassigned
— it stays `Lost` as evidence, and the replacement is a new attempt row.
Restart semantics keep the same `owner_agent_instance_id` and profile revision:
recovering a crash means re-running what the owner was running; assigning a
*different* owner is a scheduler decision (dispatch eligibility), not recovery.

The replacement id is derived deterministically from the lost attempt id and
the retry count (`"{lost-id}-retry-{n}"`), so replaying recovery for the same
lost attempt is fully idempotent: the recovery store's replay returns the same
record, and `create` of the same derived id is idempotent (byte-identical).
Recovery is per-attempt; the caller composes it with the monitor's reaped list
or with `list_in_state(Lost)` after a restart.

## Scope (this PR)

- `altai-control-plane/src/recovery_service.rs` (new): `RecoveryService`
  holding `Arc<dyn AttemptRepository>` and `Arc<dyn RecoveryRepository>`.
  - `recover_lost(&self, lost: &Attempt, failure: String, now_unix_seconds: u64,
    max_retries: u32) -> Result<RecoveryOutcome, RecoveryServiceError>`.
  - Records `record_failure(work_item_id, attempt_id, max_retries, failure, now)`.
  - `RetryQueued` → create replacement attempt (`Created`, same work item /
    owner / profile revision, timestamps `now`, id `{lost.id.value}-retry-{n}`)
    → `Recovered { replacement, record }`.
  - `DeadLettered` → `DeadLettered { record }`, nothing created.
  - `RecoveryServiceError` wraps `RecoveryError` and `AttemptError`.
- `lib.rs` exports. No protocol or storage change.

## Out of scope (follow-up packages)

- Scheduler invocation — the restart loop that calls the monitor and this pass.
- Dead-letter replay tooling / operator UI.
- Owner reassignment (a dispatch-eligibility decision, not recovery).

## Invariants

- A lost attempt is never reopened, mutated, or reassigned.
- Retries are bounded per work item; past the bound nothing is created.
- The replacement carries the same work item, owner, and profile revision.
- Replaying recovery for the same lost attempt is idempotent (derived id +
  store replay).
