# CP-08-22 — Routine command port

**Status:** in progress
**Backlog package:** 040 (second of two PRs)
**Depends on:** CP-08-21 (routine + revision contracts and repository)

## Outcome

Expose the routine abstraction (CP-08-21) over the authenticated loopback
transport: `POST /v1/routines` creates a routine aggregate and
`POST /v1/routines/{routine_id}/revisions` appends an immutable intent revision.
The transport exposes only mutations, as every repository-backed route does;
reads (`get`, `get_revision`) remain in-process. Before the wire can write the
append-only revision log, `append_revision` now enforces a monotonic intent
sequence — a genuinely new revision must advance past the current one — closing
the gap surfaced in the CP-08-21 review.

## Rationale

CP-08-21 left the routine repository in-process with no caller. Package 041
(the cron bridge) materializes a revision into Wake/RoutineRun; before that, the
host layer needs a way to author and version a routine. This PR adds that command
port, mirroring the `bind_run` / `finalize_attempt_route` pattern: thread the
repository through `ApiState`, expose POST routes guarded by `require_bootstrap`,
and map repository errors to HTTP statuses. The monotonic guard moves into the
repository because it is an invariant of the append-only log, not of transport —
so every caller (wire or in-process) is protected.

## Scope (this PR)

- `routine_repository.rs`: enforce monotonic intent `revision` in
  `append_revision` (reject `<=` the current revision's intent version) and add a
  `read_revision` helper. Idempotent replays of an already-present revision id
  remain no-ops and are exempt from the check.
- `transport.rs`: thread `RoutineRepository` through `ApiState` (9th field) and
  `router_with_control_repositories` (9th param); add `POST /v1/routines`
  (`create_routine_route`) and `POST /v1/routines/{routine_id}/revisions`
  (`append_routine_revision_route`); add the `routines()` accessor
  (503 `routine_repository_unavailable`) and `From<RoutineError> for ApiError`
  (NotFound/RevisionNotFound → 404, Conflict → 409, Internal → 500).
- `main.rs`: open a `SqliteRoutineRepository` and pass it as the 9th argument.
- No GET read routes (reads stay in-process); no scheduler wiring (package 041).

## Invariants

- The wire cannot corrupt the revision log: an out-of-order intent version is
  rejected with `Conflict` before any row is written.
- Mutations require the bootstrap bearer; a missing repository is a 503, not a
  silent no-op.
- Existing invariants from CP-08-21 are unchanged: append-only immutable intent,
  forward-only `current_revision_id`, idempotent create and append.
