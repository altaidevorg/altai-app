# CP-08-50 — Work detail and graph views

**Status:** complete
**Backlog package:** 062 (Work board/list/detail/graph) — PR 2 of 2–3,
completing the package
**Depends on:** CP-08-49 (board projection), package 060 (read-model
projections: `work_get`, `work_attempts`, `work_inbox_list`,
`work_children`)

## Outcome

A board card is now openable. Selecting a card in Home's right pane swaps
the board for a Work detail surface: description, acceptance criteria,
blocker, the attempt list newest-first with each attempt's own phase, and
the focused Work's parent and children as a graph section below.

The detail carries package 062's gate the same way the board did: status,
execution phase, and attention remain three distinct typed values
(`status: WorkState`, `latestPhase: WorkAttemptPhase | null`,
`attention: WorkInboxKind | null`), and absent axes stay `null` rather than
placeholder text. Attention renders as its own chip in the shared
`@altai/agent-ui` detail header — an additive `attentionLabel` prop —
instead of being folded into the state label. Each graph row keeps the
related Work's status as its own label, so the graph never conflates a
child's state with the focused Work's.

## Rationale

The surface composes four server projections client-side (`work_get`,
`work_attempts`, `work_inbox_list`, `work_children`) — the package 060 rule
that operational queries are answered by projections, not frontend store
joins. Failures degrade per-part: attempts, inbox, children, and parent
each fail soft to empty/null so one unavailable projection never takes the
whole detail down; only `work_get` failing (or returning null) produces the
error/not-found states. Loads are generation-guarded so graph navigation
between Work items cannot apply a stale response to the newly focused one.

The detail mounts inside Home's right pane — it does not touch the desktop
`work` destination, which still routes to the legacy GitHub project board.
Replacement and cutover stay separate PRs per the operating model.

## Scope

- `src/modules/work-board/lib/workDetailProjection.ts`:
  `toWorkDetailModel` (attempts sorted newest-first, attention = the Work's
  inbox condition, distinct status/phase/attention fields) and
  `toWorkGraphModel` (children oldest-first, a parent id that no longer
  resolves is no parent — never an unknown row).
- `src/modules/work-board/WorkDetailPanel.tsx`: container — loads
  `work_get` then the four supporting projections concurrently, each
  fail-soft; loading/error/not-found states; generation guard on navigation.
- `src/modules/work-board/WorkGraphSection.tsx`: parent + children rows,
  each a button that navigates the pane; renders nothing for a root Work
  with no children.
- `packages/agent-ui/src/components/WorkDetail.tsx`: additive
  `attentionLabel` prop — a warning chip in the header meta, distinct from
  `stateLabel`. No existing prop changed.
- `src/modules/ai/lib/native.ts`: `workGet` and `workChildren` gain the
  optional `workspacePath` override, matching `workAttempts`/`workInboxList`.
- `DesktopHome.tsx`: `selectedWorkId` state — a board card opens the detail
  in the right pane, back returns to the board, graph rows re-target it;
  reset on workspace change.
- `WORK_OS_PROGRAM_BACKLOG.md`: 062 → `accepted` (#797, #798); queue moves
  to package 063; dashboard Overall 16→18%, Product/UX 5→8%.
