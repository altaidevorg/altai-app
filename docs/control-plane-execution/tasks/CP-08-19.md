# CP-08-19 — Finalization command route

**Status:** in progress  
**Backlog package:** 035  
**Depends on:** CP-08-18

## Outcome

Expose CP-08-18's `finalize_attempt` over the authenticated loopback transport
as `POST /v1/runtime/attempts/{attempt_id}/finalize`. An observer (the host
layer, after an IsanAgent run terminates) submits one observed `RunOutcome` plus
the run-completion time; the route performs the single durable Attempt terminal
transition and returns the finalized Attempt. Finalization never completes or
mutates the bound WorkItem — that invariant is inherited from `finalize_attempt`,
which holds only an `AttemptRepository`.

## Rationale

CP-08-18 made the outcome→state translation and the idempotent, fail-closed
terminal transition testable, but it was reachable only in-process. For the
daemon to actually close the run→attempt loop, the host layer needs a single
bootstrap-authenticated command. This package threads `AttemptRepository` through
`ApiState` and `router_with_control_repositories` exactly like the existing
`run_binding_repository`, and maps each `AttemptFinalizationError` to an HTTP
status, mirroring the `bind_run` route.

## Invariants

- The route requires the bootstrap bearer credential, exactly like every other
  mutation route; an unauthenticated request is rejected before the attempt is
  read or written.
- Each `RunOutcome` serializes as a snake_case tag (`succeeded`, `failed`, …),
  matching the CP-08-18 run observation vocabulary.
- The daemon never invents the completion time: `observed_at_unix_seconds` is
  supplied by the observer and becomes the Attempt `updated_at`.
- Replay of the same outcome on an already-terminal attempt is idempotent (200,
  attempt unchanged). A divergent late observation fails closed (409); the first
  terminal observation wins.
- `NotFound` → 404, `AlreadyTerminal`/`InvalidTransition` → 409,
  `Internal` → 500.
