# CP-08-68 — Real plugin worker launcher

- **Package:** 072 — Out-of-process plugin workers (PR 2)
- **Status:** in review
- **Depends on:** CP-08-67 (#815: supervision core)

## Outcome

The reality behind the supervision core: `SupervisedWorker` owns a
plugin's worker process and its `WorkerSupervisor` as one unit. Launch
is real (`CommandWorkerLauncher` spawns a child process), observation
is real (`try_wait` reports exits the supervisor has not seen), and
every `Restart` directive is acted on immediately — the replacement is
launched before `reconcile` returns. An exhausted budget leaves the
plugin down with no process attached.

Tests spawn real child processes — the test binary re-executes itself
in a controlled mode (`WORKER_CHILD_MODE`) so exit observation is
exercised against genuine process exits on every platform CI runs on,
with no shell games.

## Rationale

- **The host owns *how* plugin code runs.** `WorkerLauncher` is a
  trait over a `WorkerCommandBuilder` the host injects: the same
  supervision drives a packaged binary, an interpreter, or a test
  double. The launcher never decides what a plugin is.
- **A replacement can die before its first probe.** The first real
  test run exposed a legal sequence the PR-1 transition table
  rejected: crash → restart → the replacement exits before it ever
  answers a probe → a crash observation arrives while the supervisor
  is already in `Crashed`. The table now accepts
  crash-from-`Crashed { exhausted: false }` — each death consumes
  budget, exactly as the total-budget rule promises. Only
  `exhausted: true` (given up, no process exists) rejects it. Real
  processes corrected the pure model; the pure test suite pins the
  corrected transition.
- **Waiting is polling, not blocking.** `try_wait` returns `None`
  while the process runs; the owner reconciles on its own schedule.
  Tests use a bounded reconcile loop for the same reason a real host
  would: a crash-mode child exits on its own schedule and the first
  poll can race it.
- **Stop is kill-plus-record, idempotent.** Killing an already-exited
  process is not an error — the fact "this process is done" does not
  change. Stopping twice is one fact.

## Scope

- `src-tauri/crates/altai-control-plane/src/plugin_worker_launcher.rs`
  (new): `WorkerLauncher` trait, `WorkerCommandBuilder`,
  `CommandWorkerLauncher`, `WorkerProcess` (try_wait/stop),
  `SupervisedWorker` (start/reconcile/stop, manual `Debug`); 6 tests
  with real child processes.
- `plugin_worker.rs`: `WorkerError::Launch`/`Process` variants;
  corrected crash-from-crashed transition + pinning test.
- `lib.rs` re-exports.

Health *probing* (asking a live worker how it feels) needs the worker
IPC transport and stays a later 072 PR: here a process that has not
exited is running, and every exit is a crash observation.
