# CP-08-29 — Evidence contract + insert-only store

**Status:** in progress
**Backlog package:** 045 (first PR)
**Depends on:** CP-08-18/19 (package 035 — terminal attempt as the verification signal), CP-08-25/26 (package 042 — governance/approval)

## Outcome

Delivers the durable, immutable evidence record: an append-only artifact reference
attributed to a specific attempt of a specific work item. This is package 045's
foundation — the gate reads "Completion requires evidence/review," and before a
quality gate can *require* evidence, the system must be able to *record* it. A
later PR consumes terminal attempts' evidence to decide whether a Work item may
complete (the finalize_attempt doc-comment names this package as the one that
"consumes the terminal Attempt to move Work disposition explicitly").

Nothing here gates completion, runs a review, or governs delivery — this is the
immutable-audit seam, mirroring how the usage ledger (CP-08-27) and approval
store (CP-08-25) each landed their contract before any consumer.

## Rationale

Evidence is execution output that proves what an attempt produced — a file path,
a diff ref, a test-result blob, a summary. Modeled as a flat, attributed,
append-only record (one artifact reference per row), it composes into a
completion gate by presence: "does this work item have evidence?" The `kind`
field lets a future gate require a specific evidence kind without enumerating
kinds now (YAGNI). Evidence is always attributed to both a work item and the
attempt that produced it, and isolated by organization.

## Scope (this PR)

- `altai-control-protocol/src/id.rs`: `EvidenceId` (`ev_`).
- `altai-control-protocol/src/evidence.rs`: `Evidence { id, organization_id,
  work_item_id, attempt_id, kind: String, reference: String,
  created_at_unix_seconds: u64 }`.
- `altai-control-plane/src/evidence_repository.rs`: `EvidenceError` (`Conflict`,
  `Internal`), `EvidenceRepository` trait, `SqliteEvidenceRepository` mirroring
  the usage/approval/budget stores (`Mutex<Connection>`, single-writer,
  idempotent record, Conflict on divergent, insert-only).
  - Table `control_plane_evidence (evidence_id TEXT PRIMARY KEY, payload_json
    TEXT NOT NULL)`.
  - `record` — idempotent on identical replay; `Conflict` on divergent same-id.
  - `get(id)` — `Option<Evidence>`.
  - `list_for_work(work_item_id)` — every evidence row for a work item (a work
    item may have evidence from several attempts).
- `lib.rs` exports in both crates.

## Out of scope (follow-up PRs)

- The quality gate (review + evidence-presence check) that blocks Work
  completion until requirements are met, and governed delivery actions. No
  Review contract, no completion transition, no transport route.

## Invariants

- Evidence is append-only: a recorded artifact reference is never edited or
  deleted.
- `record` is idempotent on identical replay and never advances anything.
- A divergent same-id record is rejected (`Conflict`); the audit never
  contradicts itself.
- Evidence is attributed to a work item and an attempt within one organization.
