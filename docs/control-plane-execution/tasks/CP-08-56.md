# CP-08-56 — Workspace audit feed

**Status:** complete
**Backlog package:** 065 (Governance, approvals, budgets and audit
dashboards) — PR 1 of 2–3
**Depends on:** CP-08-51 (transition log + `work_events`), package 060
(server projections answer operational queries), the Work OS Home
surfaces (062–064)

## Outcome

The embedded host has a workspace-wide audit surface. Home's right pane
gains a third tab — **Work | Agents | Audit** — and the Audit tab renders
the store's transition log across all Work, newest first:

- **Attributable**: every row names its Work ("State changed — Ship the
  audit feed"), and decisions (`accepted`/`returned`), stops
  (`attempt_finished` failed), and lifecycle moves each render with the
  timeline vocabulary package 063 established — one vocabulary for the
  per-Work timeline and the workspace feed.
- **Drillable**: every row opens its Work's detail surface.
- **Read-only by construction**: the audit trail is a record, not an
  editor — the surface has no mutation affordances at all.

One new read projection backs it: `WorkStore::list_recent_events(limit)`
joins `work_events` with their Work titles (newest first, bounded like
the runs hub), exposed as `work_events_recent` with `AuditEvent` in the
host contract.

## Rationale

The store has recorded every transition in-transaction since CP-08-51 —
the audit facts already existed, with no way to read them across Work.
That is the exact shape of the runs-hub gap CP-08-52 closed: the
producer exists, the read side is missing, so PR 1 is the read side.
Package 065's gate splits cleanly: decision/stop attribution and
drillability ship now; cost attribution needs a usage producer the
embedded host still lacks (the runtime emits `Usage` telemetry, the
budget engine and `UsageTracker` exist, but nothing wires one to the
other, and usage is not durable) — that wiring is the next PR of this
package, not a deferral: the producer's parts are all local to the
desktop.

## Scope

- `altai-core work.rs`: `RecentEventRecord` + `list_recent_events(limit)`
  (JOIN with `work_items`, `ORDER BY id DESC`, bounded), + test.
- `altai-core lib.rs`: re-export `RecentEventRecord`.
- `altai modules/work.rs` + `lib.rs`: `AuditEventDto` and the
  `work_events_recent` command (limit clamp 100 / default 50),
  registered after `work_runs`.
- `packages/host-contract types.ts`: `AuditEvent`.
- `src/modules/ai/lib/native.ts`: `workEventsRecent` binding.
- `work-board/lib/auditFeedProjection.ts` (+ tests): zips the timeline
  projection's label/detail with each event's Work identity.
- `work-board/AuditPanel.tsx`: load/retry/empty/list surface; rows
  drill into Work detail.
- `DesktopHome.tsx`: third `SurfaceTabs` entry; Audit renders in the
  right pane; opening Work returns to the Work surface.
- `WORK_OS_PROGRAM_BACKLOG.md`: 065 → `in_progress`.

## Out of scope

- **Cost attribution** — the durable usage ledger and the producer that
  feeds it (runtime `Usage` events → per-attempt ledger in `work.db`)
  are package 065 PR 2. The engine (`UsageTracker`, budget checks) and
  the telemetry both exist; only the wiring and durability are missing.
- Approval decision flows beyond what the detail surface already offers
  — approval attention is decisionable there today; any new decision
  affordances belong with the governance dashboards later in this
  package.
- Audit filtering/search (by Work, by kind, by actor) — a page of newest
  facts first; filters arrive when the feed has volume to filter.
