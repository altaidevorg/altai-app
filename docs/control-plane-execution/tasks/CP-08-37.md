# CP-08-37 — Protocol dispatcher and cross-transport conformance

**Status:** complete
**Backlog package:** 051 (second PR)
**Depends on:** CP-08-36 (051 PR 1 — protocol contracts), CP-08-35 (package 050 accepted)

## Outcome

Closes the 051 gate — **"Command/query/event conformance across local and
deployed transports"**. The CP-08-36 contracts become served: a
`ProtocolDispatcher` is the single seam that turns `ProtocolRequest<ProtocolCommand>`
into `ProtocolResponse<ProtocolOutcome>`, and the axum transport exposes it at
`POST /v1/protocol/commands` (plus a bootstrap-friendly
`POST /v1/protocol/negotiate`). Conformance tests prove the same request
produces the same response through the local (in-process dispatcher) and
deployed (HTTP router) transports — for successes **and** typed errors.

## Rationale

CP-15 requires one capability-negotiated API for every surface. The seam has to
be one dispatcher, not two implementations that might drift: the HTTP handler
literally calls the dispatcher, so conformance is structural, not aspirational.

Capabilities are derived from what the deployment actually serves
(`capabilities_from_wiring`) — "accurately reflects supported features without
guessing" (CP-08-36 invariant). Domains whose routes are wired (scopes, agents,
work graph, attempts, routines, approvals) advertise `true`; budgets, evidence,
activity audit, event replay, and workspace scopes advertise `false` until they
have protocol-facing serving (activity/event producers arrive with package
060; workspace-scope routes were explicitly deferred in CP-08-35).

Event replay and activity queries are therefore **capability-gated typed
errors** today, not silent 404s or guesswork: both transports answer
`PolicyDenied` identically until their producers exist. That is honest
conformance — the transports agree on every command, including unsupported
ones — and the arms are the seams package 060 fills.

## Scope (this PR)

- `altai-control-protocol/src/protocol.rs`: `ProtocolCommand`
  (`NegotiateCapabilities` | `QueryActivity` | `ReplayEvents`) and
  `ProtocolOutcome` (`Negotiated` | `Activity` | `Replayed`), adjacent-tagged
  (`{"type": ..., "payload": ...}`) for stable JSON.
- `altai-control-plane/src/protocol_dispatch.rs` (new): `ProtocolDispatcher`
  `{ deployment_mode, capabilities }` — `negotiate`, and `execute` which first
  gates the protocol major version (typed `PolicyDenied` on mismatch), then
  dispatches: negotiation answers; `QueryActivity`/`ReplayEvents` answer typed
  `PolicyDenied` unless the capability (and its producer) is present.
- `capabilities_from_wiring(...)` — honest capability set from the repositories
  actually wired into the transport.
- `transport.rs`: `ApiState` carries `Arc<ProtocolDispatcher>`; both router
  builders construct it; routes `/v1/protocol/negotiate` and
  `/v1/protocol/commands` (bootstrap-authenticated). Domain errors live inside
  the `ProtocolResponse` envelope, not in HTTP status codes.
- TypeScript parity: `ProtocolCommand`/`ProtocolOutcome` union types in
  `packages/control-contract/src/protocol.ts` + tests.
- Conformance tests: same request via dispatcher and via HTTP oneshot → equal
  responses (negotiation success, version mismatch, replay gate, activity
  gate); standalone negotiate route matches the dispatched command.

## Out of scope (follow-up packages)

- Activity/event producers and stores (package 060 read-model projections).
- Workspace-scope, budget, evidence protocol commands (routes deferred).
- Per-actor authorization of protocol commands (envelope `actor` is carried,
  not yet enforced; authn remains the bootstrap/host credentials).
- Remote worker transport hardening (package 093).

## Invariants

- One dispatcher: the HTTP handler calls the same `execute` the local caller
  calls; there is no second implementation to drift.
- Capabilities reflect wired serving; nothing advertises what it cannot serve.
- Unsupported versions and uncapable commands are typed `ProtocolError`s,
  identical across transports.
- The dispatcher never mutates; commands reach domain services only.
