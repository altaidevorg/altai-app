# CP-08-71 — Webhook delivery and scoped secrets over the worker transport

- **Package:** 072 — Out-of-process plugin workers (PR 5, closes the gate)
- **Status:** in review
- **Depends on:** CP-08-67 (#815), CP-08-68 (#816), CP-08-69 (#817),
  CP-08-70 (#818)

## Outcome

The remaining capability pair of the 072 gate scope travels on the same
one-JSON-line wire as health and jobs: a plugin with the `Webhooks`
capability can be handed inbound webhook deliveries
(`webhook_delivery` out, `webhook_ack` back), and one with
`ScopedSecrets` can be handed secret values (`secret_handoff` out,
`secret_ack` back). This closes the package's declared scope: crash
isolation, health, jobs, webhooks, scoped secrets, idempotency.

Webhooks reuse the jobs contract exactly — which is why the PR4 types
are renamed to say what they now are: `JobDispatchLedger` →
`DispatchLedger`, `JobState` → `DispatchState`, `JobDispatch` →
`DispatchOutcome`. A delivery id is sent at most once, ever, from its
own ledger (one per id family, so a job id and a delivery id cannot
collide); a completed delivery answers later awaiters from the ledger.

Secrets deliberately do **not** reuse it: a relaunched worker is a
fresh process with fresh memory, so at-most-once would break restart
transparency. Secrets are per-process state — the host remembers every
brokered value (`SecretProvision`) and re-hands the unhanded ones on
each reconcile, so a restart is invisible to the plugin.

## Rationale

- **The abstraction was earned, then taken.** PR4's ledger was
  job-shaped because it had one consumer. The second consumer arrived
  this PR, so the types generalized to `Dispatch*` at exactly that
  moment — not before.
- **Secrets must be re-sent; dispatches must not.** The restart path
  resets every `handed_to_process` flag, and `reconcile_alive` opens
  with a sweep that re-hands whatever the live process has not been
  given. A send that fails or races a death stays pending: the next
  reconcile retries, the death path resets.
- **A secret that cannot print itself.** `SecretString` redacts its
  `Debug` and `Display`; frames derive `Debug`, so a panic or a log
  line over a carrying frame shows `[redacted]`, never the value. The
  wire still carries the plain string — the worker must be able to
  read it; `expose()` is the explicit act of reading.
- **Ack/route discipline holds for the new kinds.** Webhook acks and
  secret acks arrive unsolicited like job results; each waiter stashes
  the others' evidence, so an ack landing during a probe (or a result
  during an ack wait) is delivered, not consumed.
- **Capability before any state.** Both surfaces refuse a manifest
  without their capability (`WorkerError::CapabilityMissing`) before a
  ledger entry or a remembered provision exists — an undeclared
  capability never burns a delivery id and never stores a secret.

## Real-process testing

The full-protocol child counts what it receives — requests, deliveries,
hand-offs — and reports each count on demand. The counters prove both
core guarantees: a re-delivered webhook id adds nothing (worker sees
two deliveries, not three), and a secret is handed once per process but
again after a restart (a `crash` → `jobs_exit_after_secret` → `jobs`
sequence: the middle child takes the secret, acks, dies; the well-behaved
replacement reports exactly one hand-off, made by the sweep without the
host being told again). Also covered: webhook round-trip over real
stdio; a completed delivery answering from the ledger instantly; an ack
arriving during a probe surviving it; dead-worker delivery recording
nothing; refusal without each capability; a second hand-off to the same
live process answered `AlreadyProvided`; a secret to a dead worker
remembered, not burned, and still `WorkerDown`.

## Scope

- `plugin_worker_webhooks.rs` (new): `WebhookDelivery`, `WebhookAck`.
- `plugin_worker_secrets.rs` (new): `SecretString` (redacting),
  `SecretHandoff`, `SecretAck`, `SecretHandoffOutcome`; 2 tests.
- `plugin_worker_transport.rs`: four frame variants (wire shapes
  pinned, secret redaction pinned), ack stashes,
  `await_webhook_ack`/`await_secret_ack`, `next_inbound` refactor.
- `plugin_worker_jobs.rs`: the `Dispatch*` renames +
  `record_completion` for any id family; docs generalized.
- `plugin_worker_launcher.rs`: `deliver_webhook`/`await_webhook_ack`/
  `webhook_state`; `hand_secret` + per-process provisions + the
  reconcile sweep; relaunch resets hand-off flags; child modes
  `jobs_exit_after_secret` and delivery/hand-off counters; 9 new tests.
- `lib.rs` module registrations + re-exports.
