# CP-08-53 — Attempt evidence summaries and transcript links

**Status:** complete
**Backlog package:** 063 (Runs hub and Run Inspector) — PR 3 of 3,
completing the package
**Depends on:** CP-08-50 (Work detail surface), CP-08-51 (timeline), the
attempt `result_json` and chat bindings the Work store already records

## Outcome

The Run Inspector's attempt rows now carry two inspectable facts each:

- **Evidence**: an attempt's recorded result renders as a summary line on
  its row — the failure reason from the store's failure results, the
  outcome from journal-terminated runs. A result without a readable field
  (or unparsable JSON) degrades to no line, never raw JSON.
- **Transcript**: an attempt bound to a chat renders an "Open run" action
  that switches the chat panel to that attempt's session — the transcript
  is the bound chat, not a new surface.

With this, package 063's gate is met on everything the embedded host
records: timeline (PR 1), runs hub (PR 2), attempt evidence and transcript
links (this PR). Approvals are inspectable as inbox attention — the
`approval` kind surfaces on the detail's attention chip and the Inbox,
which is the attention the embedded host produces. Delivery has no
producer in the embedded host at all — the delivery gate lives where
deliveries are recorded (the deployed backend, package 045, accepted), and
per the program's rule the desktop defers enactment that would need a
producer that does not exist.

## Rationale

The store's `result_json` is free-form JSON (failure results from the
dispatch paths, journal outcome objects from reconcile). Rendering it
verbatim would leak internal shapes into the product; parsing for the
first readable field (`failure`, `error`, `message`, `summary`) with a
length cap keeps the row a summary, not a dump. The chat binding
(`chat_id` on the attempt, written by `work_attempt_bind`) is the
transcript pointer — `switchSession` is the app's established way to open
a chat, so the link adds no new navigation machinery.

## Scope

- `workDetailProjection.ts`: attempt rows gain `resultSummary: string |
  null` (defensive parse, 200-char cap) and `chatId: string | null`.
- `packages/agent-ui WorkDetail.tsx`: `WorkDetailAttemptRow.resultSummary`
  (additive, optional) renders as a muted second line; the existing
  `onOpenRun` action is unchanged.
- `WorkDetailPanel.tsx`: `onOpenTranscript` prop wired to each row's
  `onOpenRun` when the attempt has a bound chat.
- `DesktopHome.tsx`: passes `switchSession` from the chat store as the
  transcript opener.
- `WORK_OS_PROGRAM_BACKLOG.md`: 063 → `accepted` (#799–#801); queue moves
  to package 064; dashboard Overall 18→20%, Product/UX 8→11%.

## Out of scope

- A transcript viewer inside the Work surface — the chat panel owns
  transcript rendering; the detail links to it.
- Structured evidence artifacts and delivery records — backend-owned
  (packages 045); no embedded producer exists to inspect.
- Per-attempt run inspection pages (retry actions, live phase streaming) —
  later product work once attempts stream phases to the UI.
