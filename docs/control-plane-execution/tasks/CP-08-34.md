# CP-08-34 — Workspace checkout reattachment and path resolution

**Status:** done
**Backlog package:** 050 (first PR)
**Depends on:** CP-08-11..17 (package 031 — `ProjectWorkspace` protocol type and scope store), CP-08-33 (package 044 accepted, Stage 4 complete)

## Outcome

First half of the 050 gate — **"Moved checkout keeps identity"**. A
`ProjectWorkspace` row is created once with a stable `WorkspaceId`; when the
user moves the checkout on disk, `attach_workspace_checkout` re-binds the
workspace to the new location by updating **only** `local_path_hint` (plus
`revision.next()` and `updated_at`) under optimistic concurrency. Identity,
project, name, and repository binding are untouched — the protocol type
already states the rule ("`local_path_hint` may change when a checkout moves
and is deliberately not part of workspace identity").

The other half — resolution — gets `find_workspaces_by_path_hint`: given the
location an adapter resolved on disk (e.g. `altai-core`'s
`resolve_workspace`), return the registered workspace(s) whose hint matches.
It returns every match rather than inventing an ambiguity policy (zero = not
registered; one = resolved; many = the caller must disambiguate).

## Rationale

The scope repository already owns workspace durability
(`control_plane_workspaces`, project FK enforced) but is create/get only:
moving a checkout today means either re-creating the workspace under a new id
(identity loss — exactly what the gate forbids) or nothing. Attach-on-move is
the smallest operation that satisfies "moved checkout keeps identity" without
new storage: one column of the payload changes, guarded by
`ScopeError::StaleRevision` so a stale re-attach cannot clobber a concurrent
change.

Repository-scope permissions ("fail closed") are the second PR; delivery is a
later package's executor consuming the `DeliveryGate`.

## Scope (this PR)

- `altai-control-plane/src/scope_repository.rs` (+ `sqlite_scope.rs`, +
  in-memory impl):
  - `attach_workspace_checkout(&self, workspace_id, local_path_hint,
    expected_revision, updated_at) -> Result<ProjectWorkspace, ScopeError>` —
    NotFound for unknown id; `StaleRevision` when `expected_revision` does not
    match; otherwise persists hint + `revision.next()` + `updated_at` and
    returns the updated aggregate.
  - `find_workspaces_by_path_hint(&self, local_path_hint: &str) ->
    Result<Vec<ProjectWorkspace>, ScopeError>` — exact hint match, ordered by
    id.
  - New `ScopeError::StaleRevision { entity, id, expected, actual }`.
- No protocol or schema change (hint lives inside the existing payload JSON).

## Out of scope (follow-up PRs)

- Repository-scope grants and fail-closed permission checks (050 PR 2).
- Delivery execution (package 050's executor consuming `DeliveryGate`).
- Transport route exposure.

## Invariants

- Attach changes only the hint, revision, and updated_at — identity, project,
  name, and repository binding are preserved.
- A stale re-attach fails; it never clobbers a concurrent update.
- Path resolution is exact-match and returns every match (no invented
  ambiguity policy).
