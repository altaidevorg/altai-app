# CP-08-77 — Account-aware sync and the Gmail mapping

- **Package:** 074 — Full Gmail multi-account adapter (PR 2)
- **Status:** in review
- **Depends on:** CP-08-76 (#825), 070 (#809–#812)

## Outcome

The sync engine now has an account dimension, and Gmail threads and
messages have a mapping onto it:

- **`ExternalSyncService::for_account`** — an account-scoped engine.
  Every object it maps carries the account, and the sync watermark is
  that account's alone: work's newest message never narrows personal's
  fetch window (proven by the provider recording the `since` it was
  asked — personal's first run asks for everything even though work
  already synced to 5_000). Unattributed sync (`new`) is unchanged:
  GitHub's behavior is byte-identical to before.
- **The Gmail mapping** (desktop `modules/gmail`): threads and messages
  map onto `ProviderObject`s with stable identity and stable content —
  equal mailbox entries hash equal, so an unchanged entry never writes.
  Label order is sorted before hashing (presentation, not identity);
  threads report no change clock and carry no watermark, messages
  carry `internalDate` (absent stays absent, never zero); a message
  without a thread binding is refused, not silently mapped.
- **`GmailClient` transport seam**: the provider maps; a client fetches.
  The real client — with account-scoped credentials from CP-08-76's
  store — lands with the wiring PR (074 PR 3).

The gate's three sentences now have homes: isolation and scoped
credentials shipped in CP-08-76; idempotent thread/message sync is this
PR's engine and mapping, awaiting the live client to close the package.

## Rationale

- **The watermark is per account or it is wrong.** A shared window
  would silently skip one account's changes (the newest account's
  clock suppressing the other's fetch) — exactly the leak the gate
  forbids, arriving as a sync bug instead of a data bug.
- **Mapping purity is idempotency.** The 070 rule — adapters map, never
  format — is what makes "unchanged entry never writes" true; sorting
  labels and excluding volatile ordering fields keeps the hash a
  function of meaning, not of JSON accident.
- **Seam before wire.** The provider over an injected client keeps this
  PR testable end to end without OAuth, and gives the wiring PR a
  narrow job: one client, one command.
