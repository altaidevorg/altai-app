# CP-08-40 — ControlEvent replay store and event_replay serving

**Status:** complete
**Backlog package:** 060 (second PR)
**Depends on:** CP-08-37 (package 051 — dispatcher and replay contracts), CP-08-39 (package 060 PR 1 — activity stream and dispatcher wiring pattern)

## Outcome

Second half of the 060 gate — **"Server projections, not frontend store joins,
answer operational queries"** — closes the event side. An append-only
`ControlEventRepository` (SQLite, org-partitioned, ordered by a global replay
sequence) becomes the event-sourced log; the `ProtocolDispatcher` serves
`ReplayEvents` end-to-end and flips the `event_replay` capability from typed
denial to served. A pure checkpoint fold turns replayed windows into
per-aggregate resume points — the seed read model that later projections
(inbox, board rollups) rebuild from. The daemon wires the store into
`work.db`.

## Rationale

`ControlEvent` is per-aggregate (`aggregate` + `aggregate_id` + per-aggregate
`sequence`), while the replay contract is org-scoped with one global cursor
(`since_sequence`). The store therefore keeps both orders: the per-aggregate
sequence is part of the idempotency key — re-appending the same
`(organization, aggregate, aggregate_id, sequence)` with an identical payload
is a no-op, a divergent payload is a `Conflict` — and an AUTOINCREMENT
`global_sequence` is the replay cursor, so a client checkpoint survives
interleaved appends across aggregates. Replay is org-isolated by
construction, filterable by aggregate, and resumable: `next_sequence` is the
last included row, `has_more` comes from a probe row, and pages never skip
or repeat.

Serving goes through the same dispatcher seam as every other command: the
`ReplayEvents` arm answers `EventReplayResponse` when the store is wired and
a typed `PolicyDenied` when it is not; `event_replay` in
`capabilities_from_wiring` is true exactly when the store is attached. The
denial path stays reachable and tested.

The projection seed is deliberately minimal: `fold_checkpoints` is a pure
function over a replay window that returns each aggregate's high-water mark
(last sequence and revision). It proves the contract claim — replay from a
checkpoint reconstructs projection state — without inventing domain read
models their consumers have not specified yet.

## Scope (this PR)

- `altai-control-plane/src/control_event_repository.rs` (new):
  `ControlEventRepository` trait — `append(&OrganizationId, &ControlEvent)`
  (idempotent per aggregate sequence, `Conflict` on divergent re-append) and
  `replay(&EventReplayRequest) -> EventReplayResponse` (org-scoped,
  `since_sequence` cursor, optional `aggregate` filter, probe-row
  `has_more`). `SqliteControlEventRepository` over
  `control_plane_control_events` (`global_sequence` PK, unique
  `(organization_id, aggregate, aggregate_id, sequence)`, org+sequence
  index).
- `altai-control-plane/src/control_event_projection.rs` (new):
  `AggregateCheckpoint` + `fold_checkpoints(&[ControlEvent])` — pure
  last-write-wins fold keyed by `(aggregate, aggregate_id)`.
- `capabilities_from_wiring` gains the control-event store flag →
  `event_replay`.
- `ProtocolDispatcher` holds `Option<Arc<dyn ControlEventRepository>>` and
  serves `ReplayEvents` when present; absent store keeps the typed denial.
- `router_with_control_repositories` gains the control-event repository
  parameter; the daemon opens it on `work.db`.
- Tests: store idempotency/conflict, org isolation, aggregate filter,
  replay resumability; fold ordering/last-write-wins/multi-aggregate;
  conformance for `ReplayEvents` success and denial on both transports;
  capability advertisement follows wiring.

## Out of scope (follow-up PRs)

- Domain recorders writing transitions into the log (enactment with the
  projection consumers in 061–066).
- Domain read models beyond checkpoints (inbox, board rollups) — built when
  their surfaces specify the shapes.
- Retention/compaction policy for either event stream.
- Cross-process event subscription (push); replay remains pull-based.

## Invariants

- The log is append-only; appends never mutate or reorder history.
- Replay never crosses organization boundaries; the request's organization
  is the only scope.
- The replay cursor is the global sequence — windows are stable and
  resumable across interleaved aggregates.
- Per-aggregate sequences are unique inside an org; divergence on the same
  key is a typed conflict, never an update.
- `event_replay` is advertised exactly when the store is wired; the denial
  path stays reachable and typed.
