ALWAYS-ON ML ENGINEERING

**Body**

ALTAI embeds IsanAgent, an autonomous ML engineering runtime designed to own

**Outcome examples**

## 7. Synthetic data with Afterimage

**Eyebrow**

DATASET ENGINEERING

**Headline**

Turn your corpus into training signal.

**Body**

Afterimage gives ALTAI’s ML agents a composable system for generating,
evaluating, and exporting synthetic datasets. Define the task, ground it in
your documents, diversify it with personas, and scale only after the quality
gate passes.

**Generation modes**

- Multi-turn conversational SFT data
- Document-grounded question answering
- Tool-calling trajectories
- Structured outputs
- DPO and RLHF preference pairs
- MCQ and verifiable evaluation sets
- Persona-driven and context-conditioned generation

**Quality and scale**

- LLM-as-judge and embedding-based metrics
- Auto-improve retries below the threshold
- Composite scoring and multiple judge criteria
- Async concurrent generation
- Smart API-key rotation and rate limiting
- Crash-safe incremental storage
- Live metrics, alerts, plots, and HTML analytics reports

**Export line**

ShareGPT · Alpaca · Messages · LLaMA Factory · Oumi · OpenAI fine-tune · DPO ·
Raw JSONL

**New capability callouts**

### OpenSimula

Build factor taxonomies, sample weighted scenario mixes, diversify prompts,
refine with requirement critics, and gate verifiable items with an independent
double critic.

### Context to skill

Convert large working contexts into reusable agent skills, compare candidates,
and iteratively optimize them against evaluation runs.

**Interactive scene**

dataset request, then advances through sample generation, quality rejection,

## 8. Multi-agent operations

**Eyebrow**

ORCHESTRATION

**Headline**

One agent for a task. A governed system for the project.

**Body**

Move beyond parallel chat windows. ALTAI models work as tasks with dependencies,
budgets, file scopes, quality gates, evidence, and explicit ownership.

**Feature groups**

### Plan the work

Break projects into tasks, connect dependencies as a DAG, detect cycles, and
schedule ready work across parallel runners.

### Define the team

Give each agent its own model, reasoning effort, permissions, tools, skills,
MCP servers, budget, and file scope.

### Govern execution

Apply policy checks, approval boundaries, lifecycle hooks, time/token/cost
budgets, and pass/fail verification commands.

### Inspect the run

Use the task board, activity stream, run inspector, artifact evidence,
durable event ledger, replay, and recovery surfaces.

### Improve the system

Scan repository readiness, build focused context packs, analyze sessions,
evaluate routing choices, and turn repeated success into reusable playbooks.

**Scale note**

Up to eight parallel local runners, with file-conflict detection and
agent-to-agent mailboxes.

**Interactive scene**

Switch the left rail to Project Management. A task DAG updates between queued,
running, approval, review, failed, and done states. Selecting a task reveals its
agent, budget, environment, file scope, checks, and evidence.

**Body**

Keep durable instructions beside the code. ALTAI discovers the project’s

**Configuration map**

- `ALTAI.md` — durable project instructions

- `.altai/commands/*.md` — discoverable project slash commands

## 12. Security and control

**Eyebrow**

LOCAL-FIRST BY CONSTRUCTION

**Headline**

Agents get boundaries, not blanket access.

**Body**

ALTAI keeps sensitive operations behind explicit workspace, permission, and
secret-handling boundaries. The agent can be powerful without making the
system opaque.

**Security points**

- API keys stored in the operating system keychain.
- GitHub tokens remain in the native Rust layer.
- Secret files, SSH keys, certificates, and cloud credentials blocked by
  default.
- Symlink-aware path checks and authorized workspace roots.
- Four permission modes: ask, auto-edit, plan, and bypass.
- Mutating tools respect the active approval policy.
- SSRF-hardened local-model proxy with DNS pinning and cloud-metadata blocking.
- Workspace-specific ignore rules with gitignore-style syntax.
- Reviewable diffs, checkpoints, and recoverable edits.

**Trust line**

Local first does not mean invisible. It means the evidence stays close to the
work.
