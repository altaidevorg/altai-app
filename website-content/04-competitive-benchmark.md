# Agentic Development Website Benchmark

Research date: 2026-07-29

The goal is not to copy a competitor’s visual skin. The useful question is:
**what does each site make immediately understandable, and how can ALTAI make a
larger system feel even clearer?**

## 1. Cursor

Source: [cursor.com](https://cursor.com/)

### What works

- One decisive category line.
- A product scene immediately under the hero.
- Real task language inside the visual.
- Autonomy and parallel work demonstrated as product state.
- Social proof is strong and specific.
- The new site tells a “software work system” story rather than listing editor
  features.

### Use for ALTAI

- Make the product visual carry real information.
- Use realistic task labels, not placeholder lorem ipsum.
- Show parallel work as observable state.
- Keep the first screen focused on one category claim.

### Do not copy

- Cursor’s brand palette, spatial composition, exact product-scene layout, or
  headline cadence.

## 2. Warp

Source: [warp.dev](https://www.warp.dev/)

### What works

- Owns a category: “agentic development environment.”
- Explains a system made of terminal, agents, code, and orchestration.
- Large screenshots have clear product labels.
- Local and cloud surfaces are presented as one workflow.

### Use for ALTAI

- Name ALTAI’s category confidently.
- Explain the workspace as a system of connected surfaces.
- Give each major product scene a plain factual label.

### ALTAI can go further

Warp’s narrative is still software-centric. ALTAI can own the wider,
technically coherent loop from code to dataset to experiment to model.

## 3. Claude Code

Source:
[claude.com/product/claude-code](https://claude.com/product/claude-code)

### What works

- Plain-language outcomes: map a codebase, turn issues into PRs, run tests.
- Editorial storytelling feels credible and calm.
- Shows several access surfaces without weakening the core proposition.
- Security copy explains how the product works instead of relying on a badge.

### Use for ALTAI

- Lead with outcomes.
- Explain security boundaries in sentences.
- Keep technical credibility without overloading the hero.
- Use direct section lines such as “Don’t stop at generated code.”

## 4. Kilo Code

Sources:
[kilocode.app](https://www.kilocode.app/),
[Kilo repository](https://github.com/Kilo-Org/kilocode)

### What works

- Open-source identity is central.
- Broad model choice is easy to understand.
- Community-led rapid iteration creates energy.
- IDE, CLI, and agent-manager surfaces support a flexible-workflow story.

### Use for ALTAI

- Treat model freedom and open source as system principles.
- Show extension points: skills, MCP, project commands, custom agents.

### Do not use

- Kilo terminology, Kilo configuration names, or Kilo-branded files inside the
  ALTAI product story.

## 5. Cline

Source: [cline.bot](https://cline.bot/)

### What works

- Dense feature coverage remains readable.
- “Plan-and-Act,” checkpoints, terminal execution, model choice, MCP, teams,
  schedules, and channels are expressed in concrete terms.
- Open source and infrastructure choice are part of the main narrative.

### Use for ALTAI

- The deeper feature index can be comprehensive without sounding like release
  notes.
- Pair each capability with what it lets the user control or ship.

### ALTAI can go further

- ALTAI has a stronger full-environment and ML-engineering story. The site
  should make that structural difference visible before showing a matrix.

## 6. Zed

Source: [zed.dev/ai](https://zed.dev/ai)

### What works

- Performance and native-editor identity stay present while introducing
  agents.
- Delegate, follow, review, and extend is a clean four-part model.
- Diff review and agent interoperability are shown as first-class surfaces.

### Use for ALTAI

- Keep the real IDE visible; do not let the chat composer become the entire
  product.
- Present delegation and review as two halves of the same workflow.

## 7. Replit Agent

Source: [replit.com/products/agent](https://replit.com/products/agent)

### What works

- Immediate user outcome.
- Simple “describe, build, refine” progression.
- Strong proof through recognizable customer and community outcomes.
- Production services are presented in the context of shipping.

### Use for ALTAI

- Make the first use case understandable to a technical founder as well as an
  expert engineer.
- Explain advanced capabilities after the outcome, not before it.

### Avoid

- “No coding required” framing. ALTAI’s advantage is a real, inspectable
  engineering workspace.

## 8. Bolt, Lovable, and v0

Sources:

- [bolt.new](https://bolt.new/)
- [lovable.dev](https://lovable.dev/)
- [v0](https://v0.app/)

### What works

- Prompt-first entry makes the action obvious.
- Fast path from intent to preview.
- Strong use of starter prompts and example outcomes.
- The visual editor or live preview acts as proof.

### Use for ALTAI

- Keep task starters inside the interactive product replica.
- Make it easy to imagine a first task.
- Let “Download” remain the primary action; do not recreate a fake web
  composer as the site’s hero.

## 9. Devin

Source: [Devin documentation](https://docs.devin.ai/get-started/devin-intro)

### What works

- Clear autonomous-worker metaphor.
- Backlog ownership is concrete.
- Planning, implementation, testing, and delivery are framed as one job.

### Use for ALTAI

- Speak about owned outcomes, not assistant responses.
- Show task state, budget, and evidence to make autonomy trustworthy.

## 10. Recommended synthesis for ALTAI

Take:

- Cursor’s product proof;
- Warp’s category confidence;
- Claude Code’s clear outcome writing;
- Kilo and Cline’s openness;
- Zed’s native-tool credibility;
- Replit’s immediate usefulness;
- Devin’s task ownership.

Then add what the category currently lacks:

1. one environment for both software and model engineering;
2. research before method selection;
3. pilot-before-scale discipline;
4. dataset generation as a first-class engineering surface;
5. evidence, budgets, quality gates, replay, and recovery;
6. project-owned commands, workflows, skills, and memory.

## 11. Final creative direction

**Position**

The open agentic development environment for code and machine learning.

**Visual idea**

An evidence rail moving through real ALTAI product surfaces.

**Emotional tone**

Calm control over powerful automation.

**What the visitor should understand in ten seconds**

ALTAI is a real desktop development environment where agents can code, run ML
work, generate data, and prove the result.

**What the visitor should understand in sixty seconds**

The agent can use the editor, terminal, notebooks, git, GitHub, execution
environments, skills, MCP, memory, and orchestration—but permissions, diffs,
budgets, quality gates, and recovery stay visible.
